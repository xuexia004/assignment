## 一 总体决定

以 `localwork/assignment-v1` 的 v1.0.0 元数据和当前源码为基线，沿用 Electron、React、Python、MCP 架构。较旧的 `assignment` 不作为实施目标。用户本轮取消按角色分工，后续按业务链路推进，不再按历史 Agent 文件所有权拆任务。

实施顺序为：**路径显示小修 → 获取失败恢复与评测口径修正 → 免费元数据补充及价值排序 → 篇内并发试验 → 完整桌面彩排**。Semantic Scholar 的接入可做，但默认展示流程不能依赖其匿名接口。篇内并发有先例，保留为有收益门槛的增强项，不承诺全部论文都加速。

必须交付：可缩放的路径展示；有界、可追溯的获取恢复；至少一种实际有增益的免费元数据或全文解析接入；新版排序与现有排序的对照；完整桌面展示流程及真实结果。篇内并发若未通过质量和速度门槛，交付试验结论并继续使用整篇分析。

## 三 五项改进的调研结论与实施方案

### 1 路径随面板宽度收缩并可查看全文

此处代码显示的是服务的 `data_root`，未必是源码项目目录。修改对象是可见字符串的布局，不移动实际目录、不重写配置中的路径。

采用最小改动：路径行或值所在容器允许收缩，使用 `min-width: 0`、受父容器约束的宽度及单行省略；若 flex 规则不足，改用 `auto minmax(0, 1fr)` 的两列布局。宽度跟随实际承载设置页的 Dock/面板，不能写死字符数，也不能把路径与左侧导航栏宽度错误绑定。

保留已有悬停全文；补充键盘可聚焦的全文查看或复制入口。复制成功后有简短反馈。默认不做自动跑马灯：静态省略、可控查看和复制已满足需求，且更适合投影阅读。若后续确需横向滚动，放在用户主动展开的全文区域。

验收：最窄和最宽 Dock、拖动分隔线、双组 Dock、窗口缩小、系统缩放下不撑破布局；短路径不被不必要截断；超长中文和无空格路径可查看完整内容；复制内容与真实路径一致。浏览器原生 `title` 的存在不代替键盘可用性检查。

改动范围：`frontend/src/app/layout/components/settings/SettingsPanel.tsx`、`frontend/src/app/theme/theme.css` 和已有桌面 E2E。

### 3 相关性约束下的论文价值排序

不采用“直接按被引量倒排”作为最终方案。引用量受年龄和领域影响；OpenAlex 的 `citation_normalized_percentile` 按论文类型、年份和子领域归一化，适合补充衡量引用影响。MMR 则在查询相关性与结果间冗余之间折中，适合避免 Top-k 都是同一类论文。[OpenAlex 字段说明](https://help.openalex.org/data/works/attributes/)、[MMR 原论文](https://www.cs.cmu.edu/~jgc/publication/The_Use_MMR_Diversity_Based_LTMIR_1998.pdf)。引用影响仍不是论文正确性或方法适用性的保证。

建议采用“相关性筛选 → 影响与时效轻量加权 → 多样性候选池 → LLM 精选”。这是对成熟方法的项目组合，不声称提出全新的学术算法。

1. 对全体去重候选保留现有关键词、Sentence-BERT、RRF 结果。先在原相关性排名前 40 篇内形成可重排范围；相关性明显不符或违反用户时间条件的论文不靠高引用量进入。40 是首轮可调整实验参数，不改变 LLM 最多输入 20 篇的上限。
2. 在这个范围内计算参考价值：主题相关度优先；引用影响优先采用规范化百分位；发布日期体现时效。用户明确问“近期”时才提高时效偏好；问经典方法、理论源头时不强制追新。不设置“必须有几篇老论文/新论文”的硬配额。
3. 复用已计算的论文向量实施 MMR，降低近重复内容，选择最多 20 篇交给 Selector。Selector 继续读取完整标题和摘要，增加注明来源与日期的价值信号；`final_score` 保持相关性评分语义，不能把引用分伪装成模型相关性。最终选入原因可以说明参考价值和与其他入选论文的互补关系。
4. 全体候选与原始相关性顺序继续保存；未入选论文保留确定的候补顺序。先通过实验验证新版价值顺序，再决定它是否替换当前候补顺序，不能在下载中按可获取性偷偷插队。

首轮可检验公式为 `utility = 0.80*R + 0.10*I + 0.10*F - 0.10*max_similarity_to_selected`：R 为候选范围内标准化的相关性信号，I 为规范化引用百分位，F 为按固定评测日期计算的新近度，冗余项复用向量相似度。各项取值与缺失规则必须写入审计。该权重仅是初始工程假设，先在开发题上比较，测试题不反复调参。

缺少引用指标时记为 unknown，采用中性先验而非零引用；发布日期缺失时同样不制造“新/旧”证据。第一版不把未经校准的“引用量除以年龄”混入规范化百分位；若只取得原始引用量，用于显示或单独消融。不同来源的引用量分别保留提供方和时间戳，不求和，也不把当前取最大值的合并字段当作跨库统一引用数。

所需 OpenAlex 字段放入现有 `metadata`，得分解释放入 `ranking_details`，测量放 `metrics`，优先保持冻结业务模型与 MCP 工具签名。Selector 的内部 payload 和提示词允许增量修改，但应保留旧模式用于对照。

对照至少覆盖：A 当前完整基线；B 基线加原始引用量排序这一朴素方法；C 规范化影响与时效；D 再加 MMR。A–D 使用同一候选快照、同样的完整摘要和同一个 Selector 模型配置。新增来源的收益另做一组实验，不能同时改来源与排序后把所有收益归于排序。

验收使用人工盲评的相关性 nDCG@k/Precision@k、对研究问题的参考价值评分、重复率及关键方法覆盖。引用量、余弦相似度和 LLM 自评分都只能是辅助信号，不能作为“排序质量提升”的自证指标。至少准备 6 个问题，涵盖经典方法、近期进展、方法比较；其中 2 个开发题用于选择参数，4 个保留题只用于验收。小样本只报告方向和案例，不作普遍显著性结论。

保留条件：保留题平均参考价值提高、相关性 nDCG 绝对下降不超过 0.02，且用户明确指定的原论文无新增遗漏。若没有可重复收益，保留价值解释和元数据补充，默认继续用 A，不为展示强行切换。

### 4 从 PDF 获取恢复扩展到可用材料恢复

本项优先级最高。首先承认已有能力，再补三个明确缺口：同一论文的新全文位置、不能分析时的恢复、全任务有界预算。

恢复次序如下：

`同 URL 暂态重试 → 同论文已有其他 URL → 按 DOI 查新 OA 位置 → 验证并转换 → 必要时顺位候补 → 形成实际可用报告`。

- 继续使用已有暂态重试和超时。网络失败、429、5xx 可以有限重试；明确无权限、404、非 PDF 不反复请求相同地址。缺 key、模型上下文超限和供应商额度不足也不能靠重复请求解决。
- 在准备放弃原论文前，按 DOI 用 OpenAlex/Unpaywall 查询未试过的新 OA 地址；地址去重后才下载。缺 DOI 或缺 Unpaywall 联系邮箱时跳过相应步骤。不同版本保留版本来源，不以拿到文件证明版本等价。
- 保留 Selector 的原始 `selected_papers`、原评分和原顺序；另存实际分析论文与 `original_paper_id → replacement_paper_id`、尝试地址、原因、时间和预算消耗。原论文的 PDF、摘要和失败记录一直可读。
- 新增候补触发仅针对“没有任何可分析正文”的硬失败：PDF 不可得，或取得 PDF 但转换没有正文且同篇修复已失败。部分正文有价值时继续使用并如实标记范围，不为了凑满全文数量丢掉。此规则必须明确替代当前“取得 PDF 即占位”的契约与相应测试。
- 一篇分析输出结构失败可做一次带反馈的定向修复；模型服务故障先按已有客户端策略恢复。预算/配置错误停止对应工作，不换一批论文反复耗费。此次不做模型分析失败后无限全链路重选。
- 普通主题候补按已经确定的排名前进。用户指定要分析的论文不能被另一篇冒充完成；可补互补论文，但明确保留指定对象缺失。

首轮建议：最多尝试 `2k` 篇后备论文，加原始 k 篇；额外设置 180 秒的全文获取阶段总时限，并沿用单 URL、单论文超时。这里的 `2k/180 秒` 是待实测的初始预算，不是已经达到的表现；可在固定范围内调整一次，不做开放式遍历。候补耗尽或到预算就交付 partial 和准确缺口。

指标分开计算：原始 Top-k PDF 成功率、替补后 PDF 取得数、可读正文数、完整转换数、单篇报告成功数、最终报告成功数、候补恢复数、每个恢复的额外耗时与请求数。不能用“PDF 数达到 k”替代“k 篇完整研究完成”。取消、重开和缓存命中应保持这些关系一致；恢复进度至少在每篇尝试结束时持久化，避免重连后丢失替补原因。

故障注入覆盖：403/404、429 后恢复、超时、非 PDF、无 DOI、多地址均失败、转换硬失败、部分正文、候补耗尽、预算耗尽、取消及重连。注入结果证明控制机制；另外用真实公开论文验证地址解析和正文恢复，不用合成样本声称真实成功率提高。

改动范围：`services/downloader.py`、`services/pipeline.py`、新增的简单 OA 解析函数、相关来源模块、现有配置和测试。更改判断规则时同步更新 `docs/开发契约.md`。

### 5 篇内并发采用章节感知 Map Reduce 试验

“切片之间有关联，所以不能并发”不是必然结论。PaperQA 的 `Docs.aget_evidence` 已用 `gather_with_concurrency` 并发处理 passage，再供回答阶段综合；SummN 也证明了分段生成粗摘要再综合的可行性，但其论文主要支持长文摘要质量，不证明对本项目 API 模型有固定加速比。[PaperQA 实现](https://github.com/Future-House/paper-qa/blob/main/src/paperqa/docs.py)、[SummN 论文](https://aclanthology.org/2022.acl-long.112/)。

需要区分两种任务：针对一个问题找少数证据的 RAG，可以只分析检索片段；本项目要形成整篇研究笔记，不能只取 top-n 片段后称完整阅读全文。此处建议对已提取正文做章节分组，并保证所有正文进入至少一个分析任务，再统一整合。

候选方案比较如下。

| 方案 | 判断 |
| --- | --- |
| 现有整篇一次调用 | 作为主基线；短论文通常调用开销低，仍可能是最快方案 |
| 固定字符切片并发 | 只作为廉价结构检查的参照；容易截断公式、表格与跨段论证，不作为默认方案 |
| 章节感知分组并发后整合 | 本轮唯一篇内模型试验，控制为约 3–4 组，不为每页都调用模型 |
| 每个角色都读完整全文 | 重复输入多，成本和 TPM 压力大，本轮不做 |
| 自建全量 RAG 索引、图检索、训练解析模型 | 与下周目标不匹配，不纳入本轮 |

拟议流程：

1. 复用 Markdown 标题、页映射和现有文本规则，生成章节目录及范围。短论文继续直接分析；长论文才进入分组试验。路由阈值根据第一个短/中/长样本选择后冻结。
2. 为每个分组附上相同的研究问题、标题、摘要、章节目录和少量原文引言/结论。共享材料取自原文，受大小预算约束，不为生成“全局背景”额外增加一次模型调用。
3. 按问题与贡献、方法与假设、实验与局限等章节结构组织 3–4 个并发任务；章节过长时在段落边界切，公式/表格及紧邻解释尽量成组。所有正文覆盖并记录字符范围。每组输出关键事实、条件、数字及尚未解决的跨章节引用；源片段 ID 和映射放审计，不写入用户研究正文。
4. 在整合阶段一次联合读取各组结果及相关原文上下文，检查“方法前提是否支持结论”“数字是否对应同一设置”“局限是否被遗漏”。发现跨章节依赖时定向补充原文，最多增加一次修复调用；不能让 reducer 单靠摘要猜缺失条件。
5. 某组失败只重试该组；依赖仍未解决时保留 partial，或在剩余预算足够时回退整篇分析。回退不能超出预定总调用数。

所有模型请求共用同一个全局并发和用量预算，不将“论文并发数 × 分组并发数”相乘；分析整篇和分析分组不能重复持有同一个 semaphore 导致死锁。展示初始并发上限建议仍为 2–3，复用 `asyncio` 和已有客户端，不引入新的编排框架。256000 的现有输入预算是 UTF-8 字节估算单位，不能当成供应商 tokens；对照应记录实际 input/output tokens 和限流等待。

分析时间近似为 `各组完成时间的最大值 + 整合耗时 + 排队/限流耗时`。当前单篇已只有一次调用，因此并发不保证更快；新增输出、重复上下文和整合可能使短论文变慢。接口只保证发送完整已提取正文，不保证 PDF 图表内容已被完整提取。

试验分两步：先固定 3 篇不同长度的真实 Markdown 及其哈希，整篇与章节并发各做 3 次配对；顺序交替，固定模型、thinking、输入和输出预算。若长文出现稳定收益，再对长文补到至少 5 次配对，避免用单次观察宣称加速。固定论文实验隔离分析耗时，最后还要做完整 MCP/桌面链路验证。

建议整个篇内试验封顶为 1 个工作日、60 次模型请求、500000 个供应商累计计费 tokens，任一达到即停止；这是后续实施的预算建议，本轮没有启动。先核对输入规模能否落在预算内，达不到则缩小试验并明确结论强度，不无上限追加。

启用条件：长文分析阶段的中位耗时下降至少 20%；至少 5 次配对的结果和失败数完整呈现；关键事实覆盖不下降；预先列出的核心实验数字与条件无新增错误；计费 tokens 不超过整篇基线的 1.5 倍。通过则仅对达到路由阈值的长文启用；未通过则整篇方案继续默认。小样本 p95 不稳定，应展示样本值、范围和中位数，不能伪造稳定的尾延迟结论。

当前最新契约明确删除分块流程，因此篇内试验不是改几个历史 chunk 参数；需新增显式策略并更新契约。保持当前单篇报告与总体报告接口兼容，不把旧逐字引文匹配作为成功的必需门槛。实验所需事实检查用于评价真实性，不恢复整个旧的多轮引文流程。

## 四 集成路线与止损点

以下按顺序累计估算，不是已承诺的完成日期。正式展示的具体日期未给出，因此保留最后至少 24 小时冻结和彩排；若可用时间不足，优先交付 P0，篇内并发只报告调研与试验状态。

| 阶段 | 启动条件 | 预计工作量 | 可审查交付 | 结束或转向条件 |
| --- | --- | --- | --- | --- |
| P0a 显示与评测对齐 | 从实施开始即启动 | 约半天 | 路径修复；评测兼容新旧正文、空报告仍失败；当前基线测量清单 | 桌面缩放通过，评测不再依赖新提示词已不要求的旧字段 |
| P0b 获取恢复 | 在候补语义修订明确后启动 | 约 1 天 | 同篇地址恢复、硬失败顺延、预算与完整事件；故障注入及真实公开论文结果 | 到预算如实 partial；不得为凑数无限检索或扩展 OCR |
| P1 来源与排序 | 固定基线候选与开发/保留题后启动 | 约 1–1.5 天 | 元数据补全、可选新源、排序消融及解释 | Semantic Scholar 无 key/持续 429 就保留可选；新排序无收益就保留旧默认 |
| P2 篇内并发 | 可用 Markdown、预算与全局并发约束就绪后启动 | 最多 1 天 | 长短文对照、事实覆盖、时间与 tokens | 按前述门槛启用或关闭，不侵占最后 24 小时 |
| P3 展示验收 | 选定最终算法及默认配置后启动 | 约半天，另留缓冲 | 完整桌面流程、安装/启动入口、展示题及保存的真实结果、对比表 | 有未解决阻塞就回到最后可运行配置，不在展示前临时重构 |

执行前确认工作目录与长期 `dev` 分支的关系；本轮没有切分支、提交、推送或发布。保持所有用户配置、历史、PDF、报告和密钥不变。

评测口径先版本化，旧数据只读。新增可选来源之后仍记录每源健康状态，同时区分必需来源与可选增强来源；不能因可选源失败就抹掉已有成功产物，也不能把必需源失败假装成全来源成功。

## 五 展示前的完整验收与展示内容

工程检查沿用仓库命令：`.venv-v2` 的 pytest 和 Ruff；`npm run typecheck`、`npm run test:frontend`、`npm run test:electron`、`npm run build`、`npm run test:e2e`。涉及打包服务代码时使用最终展示入口重新验证，不能只在开发窗口测试。

完整业务验收从 MainAgent 经真实 MCP Client/Server 开始，覆盖检索、去重、排序、精选、原论文获取失败、候补恢复、实际正文分析、总体报告、PDF/Markdown/笔记阅读、历史重开及导出。不能用直接调后端函数的实验替代这条链路；实验函数注入只用于隔离机制。

建议准备三种展示材料：

1. 一个真实主题的完整研究：展示问题、精选理由、论文笔记、跨论文综合和原文入口。
2. 一个明确标记的故障注入案例：前排 PDF 不可达，展示先修复同篇、再顺位候补，以及真实缺口。该案例只证明恢复机制，不计入真实成功率。
3. 一张来源、排序、恢复、耗时和 tokens 的对照表：未通过的篇内方案同样保留结论；保存的真实报告可用于现场网络波动时回放，必须标识历史运行。

讲述重点是“检索到的候选怎样更值得读、失败后怎样仍交付可用材料、长文提速是否值得额外成本”。不以新增来源数量、模型自评分或省略了工作量的时间差代替真实改进。

本轮实际变更仅为本文。没有运行测试套件或当前桌面复现，所以本文的 CSS 根因、排序效果、恢复收益和篇内加速都属于待实施验证的方案；公开接口的单次结果已在上表明确列出。
