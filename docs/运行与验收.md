本文定义安装、开发和验收入口。当前版本的检查与限制见 [v1.0.0 交付说明](v1.0.0-交付说明.md)，本次真实性能记录见[并行优化实验](并行优化真实实验_20261102.md)。下文的 v0.2.2 测试、实验与安装包记录保留其历史版本，不作为 v1.0.0 新验收结果。只有实际执行过的命令和桌面流程才可写为通过。

## 环境

- Windows 11（本轮实测）、Python 3.11+（`.venv-v2`，实测 3.13）、Node.js 22+（实测 24）、Electron 45。
- 默认 data root：`%LOCALAPPDATA%\Assignment\PaperAgent`，可用 `PAPER_AGENT_DESKTOP_DATA_DIR` 覆盖。
- 密钥只写本机 `config.json`；不要提交 `.env`、`config.json` 或用户研究资料。

## 真实运行

小规模 live 运行会访问 arXiv/OpenAlex、模型和公开 PDF，可能产生 API 用量；必须显式加 `--yes`。示例：

```powershell
.\.venv-v2\Scripts\python.exe -X utf8 scripts\stress_run.py --mode live --yes `
  --k 1 --source-limit 6 --candidate-limit 6 --merged-limit 6 `
  --max-fulltext-attempts 2 --max-llm-calls 24 --max-total-tokens 150000 `
  --max-chunks 4 --report-budget 64000 --download-timeout 180 --download-candidate-timeout 45
```

结果写入 `data/validation/v021/stress/<时间>/stress-summary.json`。PDF 下载采用单候选 45 秒、单篇总预算 180 秒、连接超时 5 秒、最多 8 个候选；超时只降级当前论文，保留错误码和中文说明。

### 真实研究实验

- 问题：`如何评估并提升 LLM Agent 工具调用的可靠性？`
- 查询：`LLM agent tool use reliability benchmark evaluation`
- 硬上限：top_k=3、60 次逻辑调用、250k tokens
- 实际用量：研究流水线 19 次调用/96,514 tokens；主 Agent 1 次/1,036 tokens；合计 **20 次 / 97,550 tokens**
- 结果：执行 `partial`，交付 `preliminary_notes`；未形成正式 `result`
- 检索：arXiv 12、OpenAlex 12，去重后 22，Selector 输入 12，真实精选 3
- 全文：2 篇完整转换、1 篇部分转换；6 次候补获取均因超时失败
- 分析：3 篇均只形成部分全文总结；报告生成但 `report_valid=false`
- 规范报告 artifact：`b50a7a02545384298340`
- 运行记录：`data/validation/real-20261028-ux-v3/`
- 未获得模型单价，因此不填写货币成本。

真实运行发现并修复了两个链路缺陷：

1. 未配置代理时，httpx 仍继承系统环境代理，导致 arXiv/OpenAlex 握手失败；来源、LLM 和共享检索客户端现与下载器一致，只使用显式配置代理。
2. 简报曾把第一条证据无条件挂给结论，造成数字结论与引文不对应；现按数字一致性和文本支持度选择引用，无可靠引用时省略结论并记录缺口。

修复后基于同一批真实总结/报告离线重算（未新增模型调用），三条结论分别定位到论文 PDF 第 9、4、2 页。直接读取原 PDF 验证：前两条完整引文命中；第三条因 PDF 连字符断词采用 17 个关键词核对，命中 16 个。原始 `run.json` 保留修复前结果作为失败证据，修复后结果存放在同目录 `postprocess-brief.json`。

### 已知边界

- 本轮真实实验没有形成正式研究结果；三篇总结均有分块证据校验失败或未覆盖全部原文，不能按全文精读或可靠研究结论交付。
- `npm run test:e2e:mock` 使用 Mock HTTP/Fake LLM；真实 API 只由上述独立 live 实验验证，二者没有混写为同一结论。
- 应用内 PDF 搜索验证了搜索词到原生查看器 URL 的路由；不同 Chromium 版本对地址搜索参数的支持仍需人工确认，不能宣称已观察原生命中结果。
- OCR 关闭，扫描件、公式、表格和语义完整性仍需人工核对。
- `frontend/src/app/tests/browser_smoke.py` 需要额外安装 Python Playwright 与浏览器，本环境未运行；其 UI 覆盖已由 Electron 集成 E2E 和前端测试替代。
- 未执行 macOS 验证、打包发布或长期性能基准。
