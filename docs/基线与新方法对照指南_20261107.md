# 基线与新方法对照指南

本轮目标是保留可实际运行的对照，展示“改了什么、相对什么基线、改善在哪个指标、还有什么局限”。采用同一份代码中的显式方法开关，不复制整套项目或覆盖历史结果。

## 一、可切换的对照档位

桌面界面已更新为 **设置 → 研究方法开关**，按环节独立选择，见[独立开关说明](研究方法独立开关_20261112.md)。下表命名档位继续供 CLI 与历史记录使用。保存仅修改新任务的默认方法，不调用模型、不重启服务、不改变已提交任务。

另有“启动时配置”（current），保留启动环境的单项配置。默认仍为 current，兼容已有使用方式。选择命名档位时，档位定义优先于单项方法环境变量；预算、模型、并发、论文数等公共控制项不随档位自动改变。

两种证据策略都只把选中原文交给模型，分析范围为 `partial_fulltext`。级联方法的新论文检索更快，但本轮真实问答 F1 较低，重复访问也未优于缓存生效的原混合检索。展示应同时呈现输入量、检索耗时、端到端耗时与回答指标，见[本轮实测](级联证据检索与版本缓存实测_20261107.md)。

`grounded` 完整保留实际提供的原文，来源范围继续由取得材料决定。其真实质量对照因生成接口故障尚未完成，当前仅可展示机制、引用回查及工程验证，不应宣称准确率提升。旧回答 F1 评分已按官方可拒答参考修正，见[质量验证与评分纠错](全文证据分析与回答质量验证_20261107.md)。

这里的基线是**本轮模块消融基线**：双方共用路径、失败候补、直接分析与评测修复，不是旧安装包或历史多轮分块流程的复刻。不通过回退共同修复来制造新方法优势。

旧手写价值加权与分段综合仍保留在代码、环境开关和原实验记录中，以上命名档位都不启用它们。需要复查负结果时使用 current 和对应单项环境变量，不改写旧测量。

若电脑仍运行本次代码更新前的旧后端，先按正常流程等待任务完成并重启旧服务一次。此后在新版本设置页切换档位无需再重启。旧记录没有档位时不补造基线标签。

## 二、记录怎样保存

- 提交任务时捕获不可变 Settings，并将无密钥配置快照写入任务；以后改设置不影响已提交任务。
- `run.json → metrics.experiment` 保存档位、模型名、thinking、论文数、各阶段并发、输入/调用预算、超时、缓存策略和配置 SHA256。白名单生成，不序列化真实凭据或完整私有地址。
- `metrics.comparison_inputs` 保存查询及候选正文指纹、Selector 候选集合指纹，以及下载器提供的 PDF 哈希。作者关键词变化也会改变正文指纹。缺失哈希保持未知，不补造。
- 性能页显示结果所属的对照配置，悬停可看配置指纹；显示依据该次结果，不取当前设置。
- 每个 run 独立保存转换 Markdown、单篇笔记、总体报告与 JSON/trace；同一篇论文分别使用 legacy/layout 不再覆盖彼此的 Markdown。原 PDF 下载缓存继续使用既有校验。
- 已开始的分阶段任务不允许换方法/预算继续执行。旧版无快照任务保持兼容读取。

配置指纹相同不保证网络返回相同；输入指纹和实际模型/来源审计仍须一起核对。来源消融预计候选集合不同；排序和解析消融应分别固定候选、固定 PDF。

## 三、统一的离线对照入口

### 回放已保存的真实测量

在命令提示符运行：

```bat
cd /d D:\学习资料\硕士\人工智能原理与应用\localwork\assignment-v1
.venv-v2\Scripts\python.exe -X utf8 scripts\compare_methods.py
```

默认不重新计时、不读取模型 key、不发网络请求。它导入已经保存的来源、四十题排序和三篇 PDF 测量，在新的 `data/validation/comparisons/<时间>/` 生成：

- `comparison.md`：课堂可读对照表。
- `comparison.json`：机器可读汇总，保留改善与退化数。
- `manifest.json`：输入 SHA256、工具代码指纹、报告工具环境版本和证据方式。
- `inputs/`：冻结的两个候选数据集和三个 PDF 副本。
- `raw/`：原始测量 JSON。
- `artifacts/`：legacy/layout 各自的全文输出。

目录必须是新目录，已有结果拒绝覆盖。输入在复制中变化、查询/gold 不匹配、排序候选集变化或 PDF 配对缺失时拒绝生成对照。工具代码指纹不冒充旧测量时的源代码指纹；历史测量的原始代码没有被追补伪造。

已生成的完整回放：[展示对照表](../data/validation/comparisons/20261107-final/comparison.md)。该文件明确标注“导入已有测量”，不能在课堂说成刚刚现场测得。

### 重新执行免费本地比较

```bat
set HF_HUB_DISABLE_IMPLICIT_TOKEN=1
set HF_HUB_OFFLINE=1
set OMP_NUM_THREADS=4
set MKL_NUM_THREADS=4
.venv-v2\Scripts\python.exe -X utf8 scripts\compare_methods.py --run --output data\validation\comparisons\my-rerun-001
```

重新运行语义/RRF 与 Cross-Encoder 配对、同 PDF 的 legacy/layout 配对；仅使用本地模型和冻结输入，0 次生成式 API 调用。模型缺失会明确失败，不偷偷下载或把关键词回退记作语义结果。来源覆盖表仍导入先前实际观察，不在此命令中请求来源接口。

`--datasets` 可显式提供两个冻结 JSON，`--pdfs` 可提供论文路径，`--sources` 可指定保存的来源汇总，`--repeats` 为 PDF 配对轮数 1–3。没有原工作区缓存时，带上上述输入或导出的数据副本。

只查看档位计划：

```bat
.venv-v2\Scripts\python.exe -X utf8 scripts\compare_methods.py --plan
```

本轮已检查重新执行分支：每组两题加一篇两页 PDF，仅作编排 smoke，不作为新效果评测。其中该两页 PDF 的 layout 略慢于 legacy，结果原样保留；不能声称所有 PDF 都加速。

## 四、整套系统的切换与对比

桌面方式直接保存对应档位后提交新任务。命令行也可显式选择：

```bat
.venv-v2\Scripts\python.exe -X utf8 -m paper_agent.cli --mode demo --profile baseline --k 3 --output-dir data\validation\baseline-demo
.venv-v2\Scripts\python.exe -X utf8 -m paper_agent.cli --mode demo --profile enhanced --k 3 --output-dir data\validation\enhanced-demo
```

这两个例子走真实 MainAgent→官方 MCP，但资料与模型是明确标记的夹具；Demo 会跳过真实来源/重排模型，不能用它们比较论文质量或速度。真实研究通过同样的档位选择执行，会按配置调用模型；本轮没有自动提交新的付费研究。

整套真实系统实验应固定问题、查询规划/实际查询、Top-k、模型与 thinking、输出/请求预算、执行方式、并发和缓存策略，并检查实际候选、作者词与 PDF 哈希。两次在线检索会变化，只有换开关不能保证严格配对；不要把候选不同、缓存不同的耗时差都归于新算法。

## 五、课堂可以怎样讲

1. 先展示档位矩阵，明确基线和单项改变；共同修复保持相同。
2. 用来源表说明覆盖增量，明确不等于相关论文或全文数量。
3. 用固定候选的 nDCG@5、Recall@20、逐题改善/退化和额外 CPU 时间说明联合重排；不外推为最终 LLM 精选更准。
4. 用同 PDF 配对时间、标题与实表对应关系说明整篇结构恢复；不把转换提速当成模型推理提速。
5. 展示综合增强可运行，再区分模块已测收益与尚未测量的端到端收益。旧分段方案的失败也可作为设计取舍，保留其真实成本与错误。

原方法和实测详情：[开源机制复用](开源机制复用与整篇解析改进_20261106.md)、[排序与篇内并发负结果](排序与篇内并发记录_20261106.md)。
