## 2026-11-02 单篇直接分析与总体报告

- 顺序模式依次分析论文；并行模式使用现有有界并发同时生成多篇单篇报告。等待全部单篇任务结束后，再将所有可用单篇报告的完整 Markdown 一起提交给 Agent，一次生成总体报告。不截取摘要或偷偷压缩报告正文。
- 新的 `analysis_input_token_budget` 默认 256000，环境变量为 `PAPER_AGENT_ANALYSIS_INPUT_TOKEN_BUDGET`；总体报告输入默认同为 256000，已有显式配置仍优先。两者使用保守 UTF-8 字节估算单位，不是供应商计费 tokens。超限时显式失败，不静默截短或恢复分块流程。历史 `chunk_chars` / `max_chunks` 保留配置兼容，不再控制新分析链路。
- 保留基本输出格式、真实论文 ID、预算和文件读写检查。PDF/Markdown 缺失、部分转换、仅摘要和模型失败继续按实际范围记录；一篇失败时，其余已生成报告可形成部分总体报告。
- `summary_scope=fulltext` 表示完整已提取 Markdown 已交给模型，不表示引文已逐字验证或结论已被独立核实。新报告中的 `evidence` 仅作为论文与报告陈述的关联，不生成伪造的引文、页码或定位。
- 新任务以 `metrics.paper_analysis` 记录单篇输入规模与调用信息，以 `report_input_audit` 记录完整报告输入；不再生成分块通过率和分块合并指标。历史报告、分块审计和已有发布实验记录保持原样可读。

## 2026-11-02 语义排序前 20 篇交给任务 Agent

- 输入区提供“并行优化”开关：关闭显式发送 `execution_mode=sequential`，开启发送 `parallel`，服务端实际执行记为 `concurrent`。开关在研究提交或运行中禁用；只影响新任务，不改写历史。性能页显示任务实际执行方式。来源检索、下载、转换和论文分析复用已有阶段依赖与有界并发，开关不修改模型、候选范围或分析预算。
- 桌面研究按全部去重候选完成语义融合排序，再按已有排名截取前 20 篇，把它们的完整标题和摘要交给任务 Agent，最后由任务 Agent 返回 Top-k；少于 20 篇时全部传入。`candidate_limit`、`merged_candidate_limit` 保留旧配置兼容，旧值不覆盖此处的 20 篇上限。候选没有额外目标插队。
- `papers` 继续保留全部有序候选，PDF 失败后的替补可以继续使用第 20 名之后的论文。审计分别记录完整候选数、实际 Agent 输入数与排除的 ID，不截断历史任务数据。
- 默认语义模块仍为现有 Sentence-BERT + RRF；原始关键词分数、语义相似度与 Agent 分数分别保留。桌面研究显式采用语义排序；CLI/实验仍可显式选择关键词排序。离线 Demo 不加载真实语义模型。
- 单次 Selector 输入上限默认提高至 256000 个保守 UTF-8 字节估算单位（历史字段名为 `selector_input_token_budget`），不是计费 tokens。总模型调用和总 tokens 上限保持原值。
- 前 20 篇（或实际更少候选）的完整标题/摘要可放入一轮时直接终选；超限时在该范围内分批完整评估、每批保留最多 k 篇，再由任务 Agent 跨批次终选。只在汇总轮限制已有模型判断文本，不截原始摘要；单篇记录无法放入时显式失败。审计记录实际评估 ID、完整摘要长度、批次与终选范围。
- 关键词仅接受明确的作者关键词字段或已取得 PDF 前两页的 `Keywords`、`Index Terms`、`关键词` 等显式栏目，保存页码和原文。OpenAlex 自动关键词和 arXiv 分类标签不冒充作者关键词。无作者词时采用标题和摘要，不为补词提前下载所有候选的 PDF。
- 语义输入中的作者词位于标题之后、摘要之前；新输入内容改变后按已有内容哈希自动使用新的向量缓存键。

## 本轮 UX 改造：阶段 1 冻结契约

本节优先于后文的历史约定。所有 JSON 字段名均使用下述 `snake_case`，Python 与 TypeScript 不使用序列化别名。新增字段只通过增量默认值兼容旧记录，不要求批量重写数据库、run JSON、PDF、Markdown 或用户配置。

### 1. 执行状态与交付状态

`ExecutionStatus` 是新外部任务的执行状态：`pending | running | completed | partial_success | failed | cancelled`。它只说明系统执行到哪里，不说明答案是否可靠。新 Job 使用 `pending` 表示排队；运行中不得提前给出最终 `delivery_status`。

`DeliveryStatus = result | preliminary_notes | no_result`：

- `result`：已有充分、可追溯证据支持的研究结果。不是 `status=completed` 的同义词。
- `preliminary_notes`：存在可用材料，但证据、阅读范围或覆盖仍有明确缺口。
- `no_result`：没有形成可可靠交付的研究答案；可以保留论文、初步材料、限制和下一步。

`PipelineResult.delivery_status: DeliveryStatus | None = None` 与 `Job.delivery_status?: DeliveryStatus | null` 独立于执行状态。Python 序列化会输出该字段；旧 API 原始记录可能缺省。新 terminal research Job 必须同时提供执行状态、交付状态与简报，Agent 8 不得根据技术完成状态自行推断 `result`。

为避免大规模迁移，`PipelineResult.status: PipelineStatus = pending` 暂时兼容旧阶段值 `searching | searched | selected | fulltexts_ready | summarized` 和旧终态 `partial | demo_completed`；Job 历史值还兼容 `queued`。这些旧值只按原义读取，新写入使用 `partial_success` 替代 `partial`，使用 `pending` 替代 `queued`。`demo_completed` 仍只表示合成示例执行完成，不能证明真实交付质量。现有 CLI 和内部流水线在阶段 2 完成适配前仍可读取旧值。

### 2. 研究简报

`PipelineResult` 新增：

| 字段 | Python 类型 | 必填/默认 | 语义 |
| --- | --- | --- | --- |
| `brief` | `ResearchBrief \| None` | 可选，默认 `None` | 新 terminal research run 必须提供；运行中或旧记录可为空 |
| `delivery_status` | `DeliveryStatus \| None` | 可选，默认 `None` | 上述交付分类，不从执行状态推导 |

`ResearchBrief` 的 JSON 结构固定为：

| 字段 | 类型 | 必填/默认 | 约束 |
| --- | --- | --- | --- |
| `findings` | `Finding[]` | 必填，默认 `[]`，最多 3 条 | 目标是 3 条，证据不足时返回实际数量，禁止占位凑数 |
| `key_papers` | `KeyPaper[]` | 必填，默认 `[]` | 只引用真实存在的 `paper_id` |
| `next_step` | `NextStep` | 必填，无默认值 | 且仅一个明确、可执行的推荐下一步；`no_result` 也必须提供 |
| `limitations` | `ResearchLimitation[]` | 必填，默认 `[]` | 说明证据/覆盖缺口及影响 |
| `report_artifact_id` | `str \| None` | 可选，默认 `None` | 唯一规范完整报告入口；不重复保存报告副本 |

子结构：`Finding.statement: str` 必填非空，`Finding.evidence: EvidenceReference[]` 必填且至少 1 条；`KeyPaper.paper_id: str` 必填非空，`selection_reason: str = ""`，`evidence_level: EvidenceLevel = metadata_only`；`NextStep.action: str` 必填非空，`rationale: str = ""`；`ResearchLimitation.description: str` 必填非空，`impact: str = ""`，`paper_ids: list[str] = []`。`delivery_status` 不在 `ResearchBrief` 内重复保存，唯一权威位置是所属 `PipelineResult`/Job，避免两个字段互相矛盾。

`ResearchReport.report_artifact_id: str | None = None` 与简报的 `report_artifact_id` 必须指向同一个 artifact。`report.markdown` 仍供旧记录和后端持久化读取，但前端聊天和首屏不得用它重复渲染整份报告。

### 3. 论文获取、阅读、证据和 artifact

`Paper` 保留现有 `status` 以兼容当前业务阶段，新增三个相互独立的维度；它们在旧记录中允许缺省/`null`，新处理结果必须按实际进度填写：

| 字段 | 类型 | 默认 | 语义 |
| --- | --- | --- | --- |
| `acquisition_status` | `not_attempted \| downloaded \| unavailable \| failed \| None` | `None` | 仅表示 PDF 是否实际取得；`pdf_url` 存在不能升级为 `downloaded` |
| `conversion_status` | `not_attempted \| converted \| partial \| failed \| None` | `None` | 仅表示 PDF→Markdown 处理结果；转换成功不等于语义完整 |
| `reading_status` | `EvidenceLevel \| None` | `None` | 当前可用于分析的最高阅读范围 |

`EvidenceLevel = metadata_only | abstract_only | partial_fulltext | fulltext`。全文是否经过分析继续由 `PaperSummary.summary_scope = fulltext | partial_fulltext | abstract_only | failed | demo_fixture` 表达；只有真实完整阅读且完成相应分析才能使用 `summary_scope=fulltext`。`fulltext_quality.complete`、页级质量和警告仍保留，不能仅因存在 Markdown 就声称语义完整。

artifact 定位字段均为 `str | None = None`：`Paper.pdf_artifact_id`、`Paper.markdown_artifact_id`、`PaperSummary.summary_artifact_id`、`ResearchReport.report_artifact_id`、`EvidenceReference.pdf_artifact_id`、`EvidenceReference.markdown_artifact_id`。artifact ID 是 job 作用域内的 opaque ID，不是本地路径。为与现有 API 兼容，确定性 ID 继续使用 `sha256((kind + ":" + (paper_id or "report")).encode("utf-8")).hexdigest()[:20]`；Agent 6/7 填写的 ID 与 Agent 8 注册的 ID 必须一致。旧记录没有 ID 时由 Agent 8 按同一规则回填公开引用，原文件不迁移。

`EvidenceReference` 保留 `paper_id`（必填）、`section`、`quote`、`claim`、`evidence_type=author_claim|system_inference|research_idea`，新增/明确：

- `page_number: int | None = None`：从 1 开始的 PDF 物理页/阅读器页，不是论文印刷页码；`page_label: str | None = None` 才保存印刷页标签。
- `pdf_artifact_id` 与有效 `page_number` 同时存在时才允许 PDF 页跳转。缺任一项必须显示“不可定位”，不得猜测页面。
- `start_char/end_char: int | None = None`：在对应持久化 Markdown 文本中的半开字符区间 `[start_char, end_char)`；必须成对提供且 `end_char >= start_char`。它们不是 PDF 页码。
- `PageMapping.page_number` 同样是从 1 开始的 PDF 物理页，`PageMapping.start_char/end_char` 继续定位持久化 Markdown；`page_map.text` 可在公共轮询结果中省略以控制载荷。

Renderer 仍只接收受控 artifact，不读取 `pdf_path/markdown_path/report_path`。`DesktopAPI.readPdfArtifact?(jobId, artifactId): Promise<PdfArtifact>` 是新增的可选兼容接口，`PdfArtifact = { data: Uint8Array; name: string; kind: "pdf" }`；Agent 10 应在阶段 2 实现完整 PDF 字节读取，Agent 9 在旧运行时接口缺失时明确降级，不能用文本接口或任意文件路径冒充 PDF 阅读。

### 4. 精选数量与执行方式

- `top_k` 字段名保持不变。Python 公共模型继续接受 `1..100`、默认 5；现有 Desktop 输入边界仍为 `1..15`，避免旧调用方和高级设置失效。`PreferredPaperCount = 3 | 5 | 8` 仅是本轮简洁 UI 的推荐集合，默认 5，不把其他合法旧值判为无效历史。
- `top_k` 是最终精选目标，不是每源检索量、合并候选量或 Selector 输入上限。候选不足时 `len(selected_papers) <= min(top_k, 可用真实候选数)`，禁止重复或虚构补足。
- 新请求 `SendMessage.execution_mode?: auto | parallel | sequential | concurrent`，默认 `auto`；`concurrent` 是旧请求中 `parallel` 的兼容别名。`parallel` 表示允许并行，`sequential` 表示顺序，`auto` 由 Agent 8/流水线按真实配置选择，不能由前端假定。
- `PipelineResult.requested_execution_mode: auto | parallel | sequential | None = None` 保存用户请求；旧记录为 `None`。`PipelineResult.execution_mode: sequential | concurrent = sequential` 继续保存实际解析后的内部模式，避免破坏 MCP 与 benchmark；`concurrent` 是 `parallel` 的实际执行名称。
- `PublicConfig.default_execution_mode` 新值为 `auto`，读取旧配置时允许 `concurrent | sequential`。`Settings.processing=serial|concurrent` 与 `Settings.execution_mode=sequential|concurrent` 保持不变，属于实际内部配置，不再兼任用户请求字段。

### 5. 旧历史数据读取策略

1. `PipelineStore.load` 继续通过 Pydantic 读取原 JSON；新增字段依赖上述默认值，不执行自动保存或破坏性迁移。旧文件只有显式后续保存时才可能增加新字段。
2. 缺少 `brief/delivery_status/requested_execution_mode` 或新论文状态时保留 `None`/缺省。UI 可沿用旧报告、总结和 `Paper.status` 展示，但必须标注旧记录未保存新维度；不得把 `completed` 自动升级为 `result`，也不得把旧 `partial` 自动升级为可靠结果。
3. 旧 `queued/partial/demo_completed/concurrent` 按上述别名和原义读取；旧 `top_k=7` 等值仍有效。旧 artifact 无 ID 时按稳定规则关联现有文件，文件缺失则显示不可读取。
4. 保留 `extra="forbid"`：这不是忽略未知损坏数据的许可。真正的旧字段适配仍按后文“旧模型迁移”执行，不能为兼容而吞掉任意字段。

### 6. Agent 5/6/7/8/9/10 数据传递

1. Agent 2/3 → Agent 4：返回真实 `Paper` 元数据、稳定 `paper_id`、来源和候选 URL；URL 不表示已下载。Agent 4 保留来源并将候选数量与 `top_k` 分离。
2. Agent 4 → Agent 5：输入去重候选 `Paper[]` 与 `top_k`。Agent 5 输出独立 `selected_papers: Paper[]`，保留 `paper_id/rank/final_score/selection_reason/ranking_reason/metadata.selection`；候选不足按实际数量返回，降级必须留下错误和审计。
3. Agent 5 → Agent 6：传递选中论文及候选身份，不传虚构本地路径。Agent 6 更新论文副本的 `pdf_path/markdown_path`、三个新状态、`page_map/fulltext_quality` 和 PDF/Markdown artifact ID；原始 `selected_papers` 选择审计不被替补覆盖。
4. Agent 6 → Agent 7：传递实际可读的论文、页映射和质量限制。Agent 7 生成 `PaperSummary[]`（含证据、范围和 `summary_artifact_id`）与一个 `ResearchReport`。为不改写未分配的 `pipeline.py`，Agent 7 新增公共纯函数 `build_research_brief(*, papers: list[Paper], summaries: list[PaperSummary], report: ResearchReport | None) -> tuple[ResearchBrief, DeliveryStatus]`；它只根据真实已有产物构建简报与交付分类，不发起新 LLM 请求、不写文件、不修改输入。每条 Finding 至少一条真实 EvidenceReference。
5. Agent 7 → Agent 8：Agent 8 在公开/持久化 Job 结果前调用上述函数，把返回值写入同一 `PipelineResult.brief/delivery_status` 与 `Job.delivery_status`，而不是自行按 status 猜测分类。报告路径仅用于受控注册；Agent 8 保证 `brief.report_artifact_id == report.report_artifact_id`（二者非空时），注册并公开 artifacts，分离 Job 执行状态与交付状态，保留 events/errors 供执行记录读取。后续若需让 CLI 的 run JSON 也包含简报，由 Agent 1 在最终集成阶段明确协调 `pipeline.py` 所有权，阶段 2 不允许越界修改。
6. Agent 8 → Agent 9：Renderer 只通过 DesktopAPI 读取 `Job{status, delivery_status, result, artifacts, events}`。首屏使用 `result.brief`，论文证据使用 `EvidenceReference`，报告只通过 `report_artifact_id` 打开；缺新字段时走旧记录兼容展示，不在前端推断成功。
7. Agent 9 ↔ Agent 10：PDF 阅读器只传 `job_id + pdf_artifact_id + page_number`；Agent 10 提供受控 `readPdfArtifact`，不暴露任意路径。页码不可定位时 UI 不跳转。

## 公共模型

| 类型 | 必需字段 | 主要扩展字段 |
| --- | --- | --- |
| Paper | paper_id, title | authors/year/abstract/doi/arxiv_id/arxiv_version/sources/source_records/paper_url/pdf_url/pdf_urls/citation_count/initial_score/final_score/rank/selection_reason/ranking_reason/ranking_details/pdf_path/markdown_path/pdf_artifact_id/markdown_artifact_id/acquisition_status/conversion_status/reading_status/page_map/fulltext_quality/status/error/errors/metadata |
| PaperSummary | paper_id | title/summary_scope/research_question/core_idea/methods/experiments/findings/limitations/relevance/evidence/author_claims/system_inferences/speculative_ideas/warnings/summary_path/summary_artifact_id/markdown/errors |
| ResearchBrief | 无（全部有默认值） | findings/key_papers/next_step/limitations/report_artifact_id |
| ResearchReport | idea | overview/related_work/comparison/researched_questions/limitations/research_directions/references/report_path/report_artifact_id/markdown/errors |
| PipelineResult | idea | run_id/query/queries/mode/execution_mode/requested_execution_mode/top_k/papers/selected_papers/summaries/brief/delivery_status/report/source_counts/timings/tool_calls/errors/metrics/status/output_dir |
| ErrorInfo | code, message, stage | paper_id/retryable/details |
| StageTiming | stage, duration_seconds | request_count/success_count/error_count |
| ToolCallRecord | tool | arguments/duration_seconds/status/controller/error |
| PageMapping | page_number | text/start_char/end_char |
| EvidenceReference | paper_id | pdf_artifact_id/markdown_artifact_id/page_number/page_label/section/quote/claim/start_char/end_char/evidence_type |
| Finding / KeyPaper / NextStep / ResearchLimitation | statement+evidence / paper_id / action / description | 见本轮冻结契约，均有明确非空与默认值约束 |
| PaperReference | paper_id, title | paper_url/doi |

`initial_score`、`final_score` 均为 0 到 1，`rank`、`page_number` 从 1 开始。`arxiv_id` 为不含版本的基础 ID，`arxiv_version` 保存 `v2` 等字符串；来源原始记录放 `source_records`。`paper_id` 必须稳定，去重后保留来源。`page_map` 保存 Markdown 中的字符起止位置，页面质量、页数和部分解析信息放 `fulltext_quality`。

`summary_scope` 限定为 `fulltext`、`partial_fulltext`、`abstract_only`、`failed`、`demo_fixture`，默认 `abstract_only`，不能在缺失全文时升级范围。`methods/experiments/findings/limitations/author_claims/system_inferences/speculative_ideas/warnings` 是字符串列表。证据类型为 `author_claim`、`system_inference` 或 `research_idea`。`comparison` 为结构化字典列表，其引用 ID 必须来自实际总结。

`Paper.status` 使用可扩展字符串，约定主状态：`metadata_only` → `selected` → `downloaded` → `converted`，失败使用 `no_open_access`、`download_failed`、`conversion_failed`、`partial_fulltext`、`failed`。`error` 提供简短人类可读原因，`errors` 保留可机器处理的信息。流水线旧阶段和终态仅按本轮冻结契约的兼容规则读取；完整成功的判定由流水线核实全文质量、总结范围、简报、交付状态和报告，不能只检查状态文字。

流水线保留 `selected_papers` 中的原始相关性 Top-k。全文候补替换记录在 `Paper.metadata` 或 `PipelineResult.metrics`，不能改写原始选择来源。`papers` 保存合并后的候选。`metrics` 可放计数、候补映射和 LLM 请求统计。`ToolCallRecord` 由主 Agent 在每次真实 MCP 工具调用后写入 `PipelineResult.tool_calls` 与 `trace.jsonl`，`controller` 区分 `model_tool_call` 与 `scripted_demo`。

## 统一模块函数

```python
async def search_arxiv(query: str, limit: int, *, settings=None, client=None) -> list[Paper]: ...
async def search_openalex(query: str, limit: int, *, settings=None, client=None) -> list[Paper]: ...
def merge_dedupe_rank(papers: list[Paper], idea: str) -> list[Paper]: ...
async def select_top_k(idea: str, papers: list[Paper], k: int, *, settings=None, llm=None) -> list[Paper]: ...
async def download_pdf(paper: Paper, *, settings=None, client=None) -> Paper: ...
async def convert_pdf(paper: Paper, *, settings=None) -> Paper: ...
async def summarize_paper(idea: str, paper: Paper, *, settings=None, llm=None) -> PaperSummary: ...
async def generate_report(idea: str, summaries: list[PaperSummary], *, settings=None, llm=None) -> ResearchReport: ...
def build_research_brief(*, papers: list[Paper], summaries: list[PaperSummary], report: ResearchReport | None) -> tuple[ResearchBrief, DeliveryStatus]: ...
```

`settings` 类型为 `Settings | None`，`client` 为可注入的 `httpx.AsyncClient | None`，`llm` 为 `LLMClientProtocol | None`。可提供持有同样依赖的类，模块函数仍保留为入口。HTTP 客户端由创建者关闭，模块不得关闭外部注入的客户端。异步函数不得阻塞事件循环；PDF 转换需线程/进程执行池。

来源失败应抛携带 `ErrorInfo` 的来源异常，由流水线收集；空列表只代表成功检索但没有结果。单篇下载和转换失败返回带状态与错误的 Paper，让其他论文继续。LLM 筛选不能悄悄退回规则排序冒充 Agent；如启用 `selector_fallback='initial_ranking'`，必须显式标记降级和原因。

## 配置与 LLM 注入

`Settings` 保留 frozen dataclass 与所有旧字段；`processing='serial'|'concurrent'` 是构造配置字段，`execution_mode` 为只读映射属性 `sequential|concurrent`。`PipelineResult.execution_mode` 使用后者。默认 Top-k 为 5、每源 20、候选 15。默认 `output_dir=data/runs`；`data_dir=data` 派生 pdfs、markdown、summaries、reports 路径，四个目录也可分别覆盖。配置不会主动创建目录。

v0.2.2 将 PDF 下载默认预算调整为单候选 45 秒、单篇总计 180 秒、连接超时 5 秒、最多 8 个候选；新增 `download_candidate_timeout` 环境变量。v0.2.1 增加四个可选规模控制字段：`merged_candidate_limit=0`（0 表示保留全部去重候选，非 0 时在排序后截取该数量进入后续阶段）、`selector_input_token_budget=0`（0 表示回退到 `llm_input_token_budget`）、`report_input_token_budget=64000`（0 表示回退到 `llm_input_token_budget`；报告提示只发送每篇前 3 条证据，完整证据保留在单篇 summary artifact 中）、`max_fulltext_attempts=0`（0 表示不限制候补下载次数）。对应环境变量为 `PAPER_AGENT_MERGED_CANDIDATE_LIMIT`、`PAPER_AGENT_SELECTOR_INPUT_TOKEN_BUDGET`、`PAPER_AGENT_REPORT_INPUT_TOKEN_BUDGET`、`PAPER_AGENT_MAX_FULLTEXT_ATTEMPTS`。`scripts/stress_run.py` 可用 40/40/30/8 档位运行，不改变日常检索与候选默认值。

注意：`dataclasses.replace(existing, data_dir=...)` 会保留已派生的四个路径。隔离实验时需同时显式设置 `pdf_dir`、`markdown_dir`、`summaries_dir`、`reports_dir`，或将其重置为 `None` 后重新派生。当前 benchmark 已分别指定四个目录。

独立并发配置为 `search_concurrency`、`download_concurrency`、`conversion_concurrency`、`llm_concurrency`。缓存配置 `cache_enabled` 与 `cache_mode=off|read_only|read_write`，基准实验必须一致。下载限制使用 `max_pdf_bytes/max_redirects/download_timeout`。来源请求采用 `http_max_retries/http_retry_backoff/http_timeout`，arXiv 请求间隔不少于 `arxiv_request_interval=3` 秒。

`llm_client.ChatClient` 与旧 `llm.ChatClient` 指向相同实现：

```python
client = ChatClient(settings, client=injected_httpx_client)
message = await client.chat(messages, tools=tools)  # 原样保留真实 tool_calls
text = await client.text(system, user)
data = await client.json(system, user)  # response_format=json_object + 本地校验
typed = await client.structured(system, user, ResponseModel)  # Pydantic 校验
counts = client.usage.to_dict()
```

`LLMClientProtocol` 仅要求 `chat/text/json`，因此测试可注入无密钥 Fake LLM。真实 `ChatClient` 要求有效地址、模型名和密钥；mock HTTP 测试用明确假的凭据。共享一个 ChatClient 才能共享并发配额和预算。密钥在 Settings repr 中隐藏，不进入调用日志、异常或源码。

超时使用 `llm_timeout`。只重试连接/超时、408、429 与 5xx；每逻辑调用最多 `1+llm_max_retries` 次 HTTP 请求。退避有上限且解析数字形式的 Retry-After。鉴权、响应结构和 JSON 错误直接失败。结构化错误通过 `LLMOutputError` 报告，预算错误通过 `LLMBudgetError`，均继承 `LLMError(RuntimeError)`。不包含服务端响应正文，以免泄露信息。

`usage.requests` 是实际 HTTP 尝试数，含失败重试；`logical_calls` 为 chat 入口调用数（含预算拒绝），`retries` 为重试调度次数。`successful_requests` 表示 Chat 响应结构有效，不代表后续 JSON 语义通过；`invalid_outputs` 单独记录 JSON/结构化校验失败。Token 数来自服务提供方 usage；缺失 usage 单独计数。`llm_max_calls` 是 HTTP 请求预算，`llm_max_total_tokens` 是已观察 Token 的停止阈值，并非精确账单保证（输入及并发请求的未知用量不能预先得知）。`llm_max_output_tokens` 限制输出，`llm_input_token_budget` 供 selector/research 估计输入预算。无真实密钥时只报告 mock 验证，不宣称真实 LLM 已运行。
