# 全文证据分析与回答质量验证

## 当前结论

已实现可切换的 `grounded`（全文证据分析）策略，并通过代码、MCP 协议和桌面验证。新方法的真实回答质量尚未验证通过：两批开发尝试受到生成接口故障影响，没有完整的四路成功对照题，因此不能据此选择方法或评价准确性、速度。60 篇最终留出尚未运行。旧实验的评分错误已修正，原始回答及旧结果继续保留。

## 先纠正评测，再定位质量问题

官方 QASPER 评分对每个问题的全部参考答案取最大 token F1，其中包含 `Unanswerable`。旧脚本删除了这种注释，误罚了缺失必要公式时的合理拒答。共用评分器已迁入 `src/paper_agent/evaluation/qasper.py`，旧、新实验入口均调用它。

| 同一批已保存回答，12 题 × 2 轮 | 旧错误评分 | 官方规则重评分 |
|---|---:|---:|
| 整篇基线 | 54.02% | 54.02% |
| 混合证据检索 | 52.38% | 60.72% |
| 级联证据检索 | 49.47% | 57.81% |

只有四条合理拒答发生改分，未重新调用模型。原“两个检索方法均低于整篇”的结论撤回；级联相对混合方案仍低 2.91 个百分点。更早另一批 48 条回答重评分没有变化。当前指标仍只是参考字符串的 F1，不是直接的事实正确率。

规范评分器与[官方实现](https://github.com/allenai/qasper-led-baseline/blob/main/scripts/evaluator.py)完成 5049 题、7993 条注释和 30294 次 F1 对照，全部一致。证据见[评分器一致性](../data/validation/quality-20261107/scorer-parity-canonical.json)、[旧结果重评分](../data/validation/quality-20261107/legacy-rescore/corrected-scores.json)。

逐题复核发现两种真实问题：一题已提供 case、number、gender 等具体特征，模型仍回答上位类别；另一题已有术语定义和解释，模型却拒答。还发现旧审查把 Newsroom/MULTI-SUM 的 P17 误记为两种上下文均包含，实际只有级联方案选入。后者不能作为级联事实退化的证据。具体原文位置与回答见[根因审查](../data/validation/quality-20261107/legacy-rescore/root-cause-audit.json)。

## 开源学习与实际移植

| 来源 | 核对的机制 | 本项目采用方式 |
|---|---|---|
| [PaperQA 固定版本 prompts](https://github.com/Future-House/paper-qa/blob/57e89f7223b0960d5ee5ea048c69e3c47e088572/src/paperqa/prompts.py) | 提取证据时保留具体数字、条件和引句，回答关联证据 | 先生成可核原句，再按问题所需粒度回答 |
| [PaperQA 证据与回答流程](https://github.com/Future-House/paper-qa/blob/57e89f7223b0960d5ee5ea048c69e3c47e088572/src/paperqa/docs.py) | 收集证据后合成回答 | 将证据输出和回答合并为一次调用，避免逐块摘要的调用开销 |
| [RAGFlow 单轮引用](https://github.com/infiniflow/ragflow/blob/a024bea0cd93f39e6652a42bf84dd20c55bc560b/agent/component/llm.py#L331) | 正常生成时注入引用要求 | 同一结构化输出生成引句与正文，随后做本地字符检查 |
| [Anthropic 长上下文实验](https://www.anthropic.com/news/prompting-long-context) | 比较先提取相关引句、再回答的读答方式 | 形成待验证假设；其 Claude 实验结果不能当作本项目 DeepSeek 增益 |

本轮也核对了 [LlamaIndex LongContextReorder](https://developers.llamaindex.ai/python/examples/node_postprocessor/longcontextreorder/) 的相关段落首尾重排机制。当前主要退化已发生在“证据存在但未正确使用”的样本上，首轮采用保留原文顺序的读答方案，减少同时改变的因素。

## 技术路线与实现边界

```mermaid
flowchart LR
  A[完整已提取原文] --> B[插入段落编号\n保留全部原字符与顺序]
  B --> C[一次模型调用\n先提取短引句，再回答]
  C --> D[本地核对段落与逐字引句]
  D --> E[研究笔记和可回查引用]
```

`grounded_context.py` 只插入段落编号，原来的标题、空白和文本均保留。引用偏移始终指向未插入编号的原文。`research_agent.py` 新增单独路由，问题放在原文之后；要求回答保留具体条目、单位、条件和实体层级。正文与引用复用现有保存、阅读及校验路径。

没有增加模型调用轮次，也没有引入新模型依赖。完整请求超预算时明确报告预算不足；不会静默压缩或追加修复调用。`fulltext`、`partial_fulltext`、`abstract_only` 仍由实际取得的材料决定；完整传入部分原文不能升级为完整论文。引句和位置正确只证明文字来自原文，不证明陈述与证据之间的语义关系正确。

桌面入口为 **设置 → 研究对照 → 全文证据分析**；CLI 为 `--profile grounded`。原 `baseline`、`evidence`、`evidence_fast` 保留，默认与综合增强档位不改为新策略。

## 固定对照设计

在任何有效模型回答产生前固定了以下设计，详见[预注册](../data/validation/quality-20261107/preregistration.json)：

- 开发：官方 train 中 12 篇独立论文，比较整篇、旧级联、全文证据先行、级联证据先行，最多 48 次请求。
- 留出：官方 dev 中未用于历史实验的 60 篇独立论文，四种主答案类型各 15 题，长短各 30 篇；保留混合注释和公式占位符。开发结束选定一个新方法，再与整篇、旧级联比较，共 180 次。
- F1 接纳门槛：点估计不低于整篇，按独立论文配对 bootstrap 的 95% CI 下界高于 -3 个百分点。该界限只是有限样本下的非劣容差，不能表述成“绝不下降”或统计等价。
- 还须检查回答失败、盲审事实支持、具体条目遗漏、误拒答及引用位置，不能只看 F1。速度和输入、输出 tokens 分开报告。
- 候选代码及提示先冻结，再运行留出。输入 hash、实际检索方法、回退、请求顺序和预算逐项落盘。失败和未执行项保留，不挑成功样本计算质量。

留出清单为 `holdout-v2/manifest.json`。初版选样发现重复论文，在任何模型请求之前已拒绝并留档；修正后的清单为 60 题、60 篇论文，与开发和历史使用论文无交集。平衡采样只代表本次验证范围，不代表实际用户问题分布。

## 服务故障与可复现状态

首批四种方法均返回 HTTP 500，第五次请求在途时停止；没有有效回答。模型列表接口返回 200，Flash 的 JSON 与普通文本生成均返回 500，另一模型的小诊断请求超时。不能据此断言所有用户都遇到服务故障。

原失败批次及账本保留在 `development-live`，单独的 `interrupted.json` 标明不可用于质量或速度评价。新 runner 已增加连续三次服务端或网络错误后停止的保护，不自动重试。数据与提示没有因故障改变，运行保护变更重新生成代码指纹。

第二批 `development-live-v2` 实际请求 15 次，8 次成功、7 次 HTTP 500，随后连续三次故障保护触发，33 个计划槽位未执行。没有一个问题完成四路成功对照，因此保留全部槽位和失败计数，只用于故障诊断；“失败记零”的均值不能解释为方法质量差异。见[第二批诊断](../data/validation/quality-20261107/development-live-v2/analysis.json)。

加上首批和三次小诊断，总计预留 23 次请求、319252 保守单位。已知成功响应报告 29815 tokens；首批的一次在途请求及诊断超时没有最终 usage，不能将未知用量视为零。剩余请求额度为 217 次。为在原 240 次上限内恢复实验，预先另存修订方案：重做开发 48 次，最终仅做整篇与选定新方法的 60 题主要对照（120 次），再做 4 次正常报告路径验证；取消最终的旧级联次要对照。主基线、60 篇清单和接纳门槛不变，也没有读取留出模型结果。详见[预算状态](../data/validation/quality-20261107/budget-status.json)和[故障后预算修订](../data/validation/quality-20261107/amendment-provider-outage.json)。

恢复后的开发复现入口（需要可用模型服务，凭据由隐藏输入读取）：

```bat
cd /d D:\学习资料\硕士\人工智能原理与应用\localwork\assignment-v1
```

省略 `--live --yes` 可预检输入和实现 hash，不读取凭据、不发模型请求。输出目录必须新建，禁止覆盖旧账本。开发未完成前不运行留出，避免把最终验证集用于选择提示。
