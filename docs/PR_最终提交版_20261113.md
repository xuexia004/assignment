本 PR 围绕论文 Agent 的“检索 → 全文准备 → 证据分析 → 综合报告”链路，加入 **Cross-Encoder 联合重排、CPU 版面解析、篇内混合/级联证据检索、全文证据先行和结构化报告生成**，并提供逐环节基线开关与可追溯实验记录。课程展示可以对应说明双阶段检索、稀疏与稠密检索融合、父段上下文恢复、引用约束和结构化生成的作用。

工作以成熟开源机制的学习、适配和本项目实测为依据。保留原有 MCP 工具编排、语义/RRF 排序、LLM Selector、整篇直接分析与多篇并行，新增方法接入同一运行链路；基线和新方案可切换，未建立优势的策略保留实验标记。

## 新增方法与对应基线

| 环节 | 原方法/直接对照 | 本轮新增机制 |
| --- | --- | --- |
| 候选论文排序 | 关键词、Sentence-BERT 与 RRF 融合，再由 LLM Selector 精选 | **Cross-Encoder 双阶段检索**：对原前 20 篇联合读取问题及标题/关键词/摘要，重新排序后交给原 Selector；前 20 候选集合不变，第 20 名之后顺序不变 |
| 价值排序实验 | 原语义/RRF 排名 | **引用与多样性加权**：组合归一化引用百分位、发表时效与 MMR 相似度惩罚；修订版保护原 Top-k，实测未建立收益，保留为关闭的实验对照 |
| PDF 全文转换 | PyMuPDF4LLM legacy 路线 | **CPU layout 解析**：恢复阅读顺序、章节标题与表格结构，导出完整 Markdown 后仍可一次分析；异常回退 legacy |
| 篇内证据选择 | 整篇直接分析；评测另设前缀、BM25、纯向量对照 | **混合证据 RAG**：BM25 与 MiniLM 向量经 RRF 融合，前 20 子块 Cross-Encoder 重排，恢复父段、按原文顺序打包并生成带引句的笔记 |
| 篇内检索加速 | 上述 hybrid 对全文子块计算向量 | **cascade40 级联检索**：BM25 先筛前 40 子块，再 Cross-Encoder 精排；减少全文向量编码，复用父段恢复、预算和引用检查 |
| 整篇证据使用 | `direct` 全文一次生成 | **grounded 证据先行**：保留全部已提供文本，插入段落编号，在一次生成中先提取引句再回答，随后核对引句与原文位置 |
| 长文篇内并发 | `direct` 一篇一次调用 | **sections 分段 map–reduce**：长文分段并行分析，共享引言/结论与目录，综合时可回看原段；作为实验路线保留 |
| 综合报告 | 一次输出完整 Markdown 及多组结构字段 | **structured 结构化生成**：只生成结构字段，严格校验后本地排版；格式/明确长度截断最多额外生成一次，旧 `legacy` 独立保留 |
| 元数据来源 | arXiv + OpenAlex | **Crossref 补充来源**：经原 MCP 检索入口获取并去重题录，保留来源健康状态，补充源失败不阻断核心来源结果 |

候选论文重排与篇内子块重排位于不同环节。`direct / evidence / evidence_fast / grounded / sections` 是同一单篇分析环节的替代方案，不会把这些方法全部串行叠加。对话区原有“并行优化”控制不同论文之间的调度，与篇内分段并发分开。

## 技术机制与开源学习来源

**1. 先召回、再联合重排。** 采用本地 `cross-encoder/ms-marco-MiniLM-L6-v2`，让模型联合判断问题与候选文本的相关性。仅重排原前 20 篇，保留原关键词、余弦、RRF 与 Selector 分数；模型缺失或评分异常时保留基线，不在研究任务中临时下载权重。参考 [Sentence Transformers 的 Retrieve & Re-Rank](https://www.sbert.net/examples/sentence_transformer/applications/retrieve_rerank/README.html)，实现入口为 `services/cross_encoder_reranker.py`。

**2. 先恢复文档结构，再让 LLM 阅读整篇。** 使用项目锁定的 PyMuPDF/PyMuPDF4LLM 1.28.2，切换到公开 layout 路线，不新增常驻解析服务或逐段生成调用。保留实际解析器、页映射、原 PDF 和回退记录；当前关闭 OCR，复杂公式/图片仍不等于已被模型理解。采用 [PyMuPDF4LLM 的 CPU 版面能力](https://pymupdf.readthedocs.io/en/latest/pymupdf4llm/)，实现入口为 `services/pdf_converter.py`。Docling、GROBID、Marker、MinerU 等保留在调研记录中，本 PR 没有部署这些框架。

**3. 用小块检索、用父段回答。** 篇内 hybrid 按约 900 字符、120 字符重叠构造子块，用 BM25、MiniLM、RRF 和 Cross-Encoder 选证据；生成前恢复父段，以最多 12,000 UTF-8 字节打包原文，记录字符偏移、段落编号及文本哈希。cascade40 将召回阶段换成 BM25 前 40 子块，省去全文子块的向量计算。两路均一次生成研究笔记，再检查引用编号和逐字引句，实际材料范围标为部分全文。借鉴 [PaperQA 的问题驱动证据收集](https://github.com/Future-House/paper-qa#paperqa2-algorithm) 与 [LlamaIndex 的父上下文恢复](https://raw.githubusercontent.com/run-llama/llama_index/main/llama-index-core/llama_index/core/retrievers/auto_merging_retriever.py)，按本项目预算和 MCP 接口实现；没有引入其整套框架或复刻多级递归合并。入口为 `agents/evidence_context.py`。

**4. 为全文阅读保留另一条证据路线。** `grounded` 不裁剪已提供原文，只添加段落定位，在同一次调用内要求先引用再回答，降低选段遗漏的风险。机制参考 [长上下文先提取相关引句再回答的实验](https://www.anthropic.com/news/prompting-long-context)；本项目的真实质量对照尚未完成，不能套用其他模型的收益。`sections` 则对至少 4 万字符长文尝试约三段 map 加一次 reduce，并共享全局调用并发上限；其调用数增加和跨段信息损失保留为实验取舍。入口为 `agents/grounded_context.py`、`agents/section_analysis.py`。

**5. 将报告内容生成与展示排版分开。** `structured` 保留全部可用论文笔记，让模型只生成综述、相关工作、比较、研究问题、局限、研究方向和参考文献等字段，本地渲染 Markdown，减少完整正文与结构字段重复输出。比较项必须覆盖全部输入论文；已知论文身份、引用与字段类型仍严格检查。至多一次额外生成使用完整笔记和安全的错误提示；网络故障、预算不足或取消不走格式修复。两条报告路线原本都使用 JSON 输出，本次改变的是输出任务与校验/恢复流程。入口为 `agents/research_agent.py`。

Crossref 通过官方公共 REST 接口接入，无需模型请求；来源补充遵循 [Crossref 的公共访问方式](https://www.crossref.org/documentation/retrieve-metadata/rest-api/access-and-authentication/)。题录或全文链接存在，不代表一定有摘要、可下载 PDF 或更高相关性。

## 已有模块对照结果

以下来源、排序、解析与检索结果来自 **11 月 6–7 日冻结输入的模块实验**，分别回答对应阶段的问题；不是修复后完整系统的一次综合消融，不将不同样本或阶段的改善比例相加。

| 方法 | 对照条件 | 实测结果 |
| --- | --- | --- |
| Crossref 补充 | 同一批三组检索记录，保留/移除该来源 | 去重候选 **28→43、26→36、29→40**；增加的是题录覆盖 |
| Cross-Encoder 重排 | 两组各 20 个查询，候选池分别 146/141 篇 | nDCG@5 **0.719220→0.806546、0.748784→0.915853**；Recall@20 分别保持 0.975、0.908333 |
| CPU layout | 同三篇 PDF，每种方法各两轮 | 转换中位耗时 **11.02→4.79、5.85→4.95、3.20→2.50 秒**，分别减少 56.6%、15.4%、21.9% |
| cascade40 新论文证据准备 | 12 篇×2轮，独立进程、模型预热后清空文档向量缓存 | hybrid 中位 **1.894 秒**，cascade **0.850 秒**；同题同轮耗时比的中位数下降 **52.8%** |

排序结果来自“固定背景候选＋gold 元数据”的构造集合，第一组参与过重排范围选择，第二组此前用于价值规则评测；不是完整 LitSearch 或独立盲测。Recall@20 不变由保持前 20 集合保证，不是新的召回收益；每组仍有退化问题，也尚未验证最终 LLM Selector 的收益。PDF 计时不含下载或 LLM，结构和复杂表格仍有遗漏，不能当成回答准确率提升。

篇内检索还使用 QASPER 人工证据做冻结评测。新增 98 篇、每篇一个问题、相同 12KB 预算下，BM25/hybrid/cascade 的证据覆盖率为 **82.41% / 88.30% / 89.11%**，完整证据集命中为 **74/98、81/98、81/98**。cascade 相对 hybrid 的覆盖差为 +0.81 个百分点，95% 配对区间为 [-5.00,+6.77]，不足以确认更准或等价。

随后固定其中 12 个问题，各两轮三方法，共 72 次真实模型回答，按包含可拒答注释的官方规则重评分。三路使用统一英文短答案提示词，切换的是输入上下文；这是问答对照，不是应用 `direct` 长篇研究笔记的质量指标：

| 方法 | 平均 Answer F1 | 每方法 24 次输入 tokens | 首轮 / 第二轮回答总耗时中位数 |
| --- | ---: | ---: | ---: |
| 整篇输入 wholetext（问答基线） | 54.02% | 151348 | 1.071 / 1.072 秒 |
| hybrid 混合证据检索 | 60.72% | 65478 | 2.882 / 1.314 秒 |
| cascade40 级联证据检索 | 57.81% | 66252 | 1.709 / 1.855 秒 |

这些数据支持减少模型输入：cascade 比整篇少 **56.23%**。它比 hybrid 的 F1 低 2.91 个百分点，整篇在本组回答计时中仍更快，缓存也会改变速度关系。独立样本只有 12 个问题，F1 是参考答案词重叠而非事实正确率；不能宣称回答质量不下降或整体提速。这里的回答总耗时仅含证据准备与 LLM，不含系统的论文检索、下载和报告。

## 最终结构化报告复验

11 月 16 日最终修订版单列 **三组配对**：同一五篇论文的完整固定笔记、同模型 `deepseek-flash`、相同 4000 输出 token 上限，交替运行旧版和新版。

| 指标 | legacy 旧报告 | structured 新报告 |
| --- | ---: | ---: |
| 可读且严格校验通过 | 0/3 | 3/3 |
| 报告阶段耗时中位数 | 22.81 秒 | 9.27 秒 |
| 耗时范围 | 21.89–23.17 秒 | 8.85–9.80 秒 |
| 三次输出 token 合计 | 12000 | 4532 |
| 额外格式恢复调用 | 0 | 0 |

旧版三次均达到输出上限而被拒收，新版均首次生成通过；报告阶段耗时中位数减少约 **59.3%**。旧版计时为失败尝试耗时，新版输出更精简，不解释为等篇幅或端到端成功交付加速。首批另六对为开发版本的 0/6 对 6/6，不能合成最终版九次验证。一次恢复分支由合成错误回归覆盖，真实样本没有测得其独立挽救率。人工复核仍有成本口径及无依据否定判断，不保证事实准确率。

## 可靠性与可展示的实验控制

- **强化已有 batch 替补**：旧版已有按排名分批补位；本轮将成功标准从拿到 PDF 改为获得可读 Markdown，增加阶段总时限、后备尝试上限、逐篇落盘及失败记录，修复来源排队侵占单地址下载预算的问题。运行版不采用此前未建立稳定优势的滚动替补或渐进短超时。
- **独立开关**：来源、候选排序、PDF 解析、单篇分析和报告分别设置；同环节方案互斥、跨环节可组合。保留直接分析与 legacy 报告，“全部恢复基线”可用于模块消融，原有多篇并行独立控制。
- **预算与界面**：默认、慢速网络、自定义时间预算均可编辑保存；修复长路径溢出。设置只影响新任务，旧任务保持配置快照。
- **可追溯与缓存**：记录模型/配置指纹、候选与正文哈希、实际策略及回退；按 run 隔离解析和报告，按 arXiv 版号校验 PDF 缓存及派生关键词，避免不同版本混用。保留原始失败和长尾，不事后删除慢样本制造优势。
- **评测纠错**：统一 QASPER 全注释评分，恢复合理拒答参考；修正历史分数并保留原回答和原记录。可用 `compare_methods.py`、排序/PDF/证据评测脚本进行分阶段复核，生成调用须显式启用。

默认采用 Crossref、layout、direct 单篇分析和 structured 报告；Cross-Encoder 可选且默认关闭，需要本地语义依赖与缓存权重。已有显式用户配置优先。旧手写价值规则和 sections 分段并发保留负结果，未作为已验证的效果提升。

## 验证与交付边界

当前提交版本完成：Python **563 通过/3 在线项跳过**，前端 **18 通过**，Electron **19 通过/1 安装包项跳过**，桌面 E2E **24 组通过**；Ruff、类型检查、生产构建通过。E2E 使用离线 fixture，覆盖官方 MCP、方法开关、预算保存与结构化报告，不计作模型效果实验。本次未验证新安装包、全新依赖安装或远端跨平台 CI。

修复前完整 33 轮消融为可读报告 4/33、严格报告 0/33，固定回放还复现了新旧共有的输出截断；这些负结果仍保留，报告修复后未重跑完整消融。新增证据路线仍有 `citation_quote_mismatch`，下载长尾和部分事实判断仍未解决。因此本 PR 的效果结论按阶段给出，不宣称整套系统稳定更快、更准。
