# 级联证据检索与版本缓存改进

> 2026-11-07 后续质量审查纠错：旧回答评分漏掉了 QASPER 的 `Unanswerable` 参考注释。下方回答表已更正，原始请求、回答和旧结果文件保留。检索覆盖率和计时不受影响。旧“级联回答 F1 低于整篇”的结论撤回。

## 改进目标与实现

上一轮篇内检索在减少 LLM 输入的同时增加了等待时间。本轮针对新论文逐段向量编码的开销，移植“词法召回后联合重排”的级联路线，并保留原混合检索及整篇分析作为对照。

级联路线为 BM25 全文子块初筛 → 前 40 子块 Cross-Encoder 联合评分 → 恢复父段 → 12KB 原文预算打包 → 一次 LLM 分析与引用核对。原 hybrid 路线仍为 BM25 与全篇 MiniLM 向量 RRF 融合后重排前 20 子块。两路共用段落划分、预算、父段恢复、原文排序与引句核对。

复用了本地现有模型和依赖。Sentence Transformers 官方文档明确支持词法召回或向量召回后进行 Cross-Encoder 精排。本机的收益需要实测确认。[检索与重排文档](https://www.sbert.net/examples/sentence_transformer/applications/retrieve_rerank/README.html)

ONNX INT8 也做了调研。官方固定模型版本存在 AVX2 量化权重，本轮采用已验证的级联方案，推理后端继续使用已有 PyTorch，安装依赖保持当前环境状态。[Cross-Encoder 加速文档](https://www.sbert.net/docs/cross_encoder/usage/efficiency.html)

桌面新增“级联证据检索”，CLI 对应 `--profile evidence_fast`。设置仅改变单篇分析策略。原“篇内证据检索”对应 `evidence`，整篇对照对应 `baseline`。新策略分析范围仍为 `partial_fulltext`，引用的位置核对与陈述事实正确性分开评价。

## 开发选择与未见论文验证

首次只重排 BM25 前 20 子块时，开发集证据覆盖率从原方法的 95% 降至 85%，未通过门槛。该负结果保存在 `dev-run1`。开发阶段只再尝试一次更宽的 40 子块候选池，覆盖率恢复到 95%，与原方法逐题相同。

随后冻结参数，在官方 QASPER test 的剩余 98 篇合格论文上评估。它们与旧 100 篇留出、开发 20 篇均无论文交集。每篇一个具体英文问题，正文至少 24KB且具备可定位人工证据。所有预算方法共享 12KB UTF-8 字节上限，gold 只用于事后评估。

| 方法 | 人工证据覆盖率 | 完整证据集命中率 |
|---|---:|---:|
| BM25 | 82.41% | 75.51% |
| 原混合检索 hybrid | 88.30% | 82.65% |
| 新级联检索 cascade40 | 89.11% | 82.65% |

级联相对原 hybrid 的差值为 +0.81 个百分点，按论文配对 bootstrap 95% CI 为 [-5.00,+6.77] 个百分点。当前结果不足以确认更准或统计等价。相对 BM25 为 +6.70 个百分点，区间为 [+2.31,+11.85]。

## 本地新论文处理速度

独立进程对同一 12 篇论文运行两轮，反转方法与论文顺序。模型预热单独计，每题清空向量缓存，记录模型已加载时处理新论文的耗时。

| 指标 | 原 hybrid | cascade40 |
|---|---:|---:|
| 新论文检索耗时中位数 | 1.894 秒 | 0.850 秒 |
| 两轮冷启动文档 | 12.24 / 12.93 秒 | 11.37 / 11.93 秒 |

按同题同轮配对的耗时比中位数为 0.472，即减少 52.8%。冷启动收益较小，模型导入与加载仍占主要部分。上述数字只覆盖本地证据准备，生成总耗时单独报告。

正式计时见[独立进程计时](../data/validation/cascade-20261107/latency-isolated/result.json)。早先中断的计时目录留有 `interrupted.json` 标记，未用于结果结论。

## 三路真实模型回答对照

从新留出清单固定取前 12 题，每题 2 轮、3 个方法，共 72 次 QA 请求。DeepSeek Flash、关闭 thinking、temperature=0、输出上限 512 tokens，各方法使用相同回答提示。每题轮换方法位置，下一轮反转顺序。模型看到的上下文、原始回答、调用顺序和用量全部保存。

| 指标 | 整篇 wholetext | 原 hybrid | cascade40 |
|---|---:|---:|---:|
| 回答 F1（官方全注释重评分） | 54.02% | 60.72% | 57.81% |
| 24 次输入 tokens 合计 | 151348 | 65478 | 66252 |
| 首轮端到端中位数 | 1.071 秒 | 2.882 秒 | 1.709 秒 |
| 第二轮端到端中位数 | 1.072 秒 | 1.314 秒 | 1.855 秒 |

级联比整篇减少输入 56.23%，但本批样本中整篇回答仍更快。级联比 hybrid 的首轮逐题耗时比中位数为 0.612；第二轮为 1.401，即慢约 40.1%。原方法第二轮复用了向量缓存，级联方案没有该项节省。

QA 首题 hybrid 承担了共享模型的首次加载，随后 cascade 复用已加载的 Cross-Encoder；服务商缓存状态也不可控。因此，主速度证据使用上节独立进程实验。补充敏感性分析排除首题后，首轮余下 11 题级联/hybrid 耗时比中位数为 0.627，仍减少约 37.3%，但相对整篇仍慢约 54.8%。这不证明任意查询或正式长报告都能提速。

独立统计单位是 12 个问题，先对同题两轮求均值。官方评分保留每条注释，并对所有参考答案的 token F1 取最大值，包括无法回答的参考。旧脚本过滤后将第 8 题的四条合理拒答判零；原文公式仅剩占位符，人工注释也包含无法回答。修复后级联减 hybrid 仍为 -2.91 个百分点（原配对区间 [-13.04,+4.69] 不变），级联减整篇改为 +3.78 个百分点。旧对整篇差值 -4.55 及其区间失效；样本量有限，不能据此宣称质量更好或等价。见[官方评分代码](https://github.com/allenai/qasper-led-baseline/blob/main/scripts/evaluator.py)、[新建重评分结果](../data/validation/quality-20261107/legacy-rescore/corrected-scores.json)。

人工复核主要差异：MULTI-SUM/Newsroom 题旧审查误称两路均包含解释二者关系的 P17，实际只有 cascade 选中了 P17；这题不能当作 cascade 事实退化的证据。语言列表题受列举详略影响。形态特征题则存在实际粒度退化：细粒度证据已被选入，回答仍给出宽泛类别；复杂性/混淆性题的解释也已在原文中，三个方法却全部拒答。证据召回改善不自动等于模型回答改善。逐题原文位置和核对见[根因审查](../data/validation/quality-20261107/legacy-rescore/root-cause-audit.json)。

原始数据见[真实模型结果](../data/validation/cascade-20261107/answers-live/result.json)、[逐题独立统计与复核](../data/validation/cascade-20261107/answers-live/analysis.json)。既有整篇与 hybrid 策略继续保留；新级联档位作为新文档证据准备速度和输入成本的实验选项，不进入默认或综合增强档位。

## 正常报告路径与预算

另用前两篇文本调用正式 `summarize_paper` 入口，对 direct 与 evidence_fast 各生成一次中文分析，输出上限统一为 2048 tokens。4 次均成功，级联两份报告包含的 10 条引句全部与原文字符范围逐字一致。它验证正常分析函数、报告保存和引用回查；输入来自 QASPER 已提取文本，没有据此验证 PDF 提取质量或端到端检索任务。报告内容和长度不同，这 4 次时延不用于速度优越性结论，引句位置正确也不等于报告陈述均正确。

本轮总计 76 次实际请求全部成功，无重试或无效输出。供应商报告输入 301604、输出 6023、合计 307627 tokens。预算账本预留 1448597 保守单位，低于已定 3000000 单位/80 次上限；保守单位按输入 UTF-8 字节加输出上限计算，不能用于推算账单。见[预算账本](../data/validation/cascade-20261107/answers-live/budget.json)。

## arXiv 版本缓存修复

审查发现相同 arXiv 论文的 v1/v2 具有相同 paper_id，原 PDF 缓存仅按 paper_id 定位。请求新版时可能读取旧版缓存，新下载也可能覆盖旧路径。作者关键词读取也沿用同一旧路径，可能把旧版关键词传入新版论文排序。

改为以论文标识和明确版号确定缓存身份，写入 manifest 并校验。不同版本具有不同缓存文件。只有官方 arXiv PDF URL 的合法标识可用于推导版本，模糊候选避免缓存复用。跳转链中明确不匹配的官方版本也被拒绝。

新版请求携带旧版派生数据时，清理结果副本中的旧 PDF/Markdown 路径、页映射与相应质量、关键词信息。历史文件和原输入对象继续保留。作者关键词读取与独立 PDF 转换共用版本身份，避免下游路径退回只按 paper_id 处理。正常研究任务本来已有按 run 隔离的转换目录，独立转换入口也补充了版本隔离。

此项采用生成 PDF、受控 HTTP/DNS 与原文路径回归验证，验证缓存身份和状态正确性，不涉及论文生成质量评分。

范围限制：非官方镜像无法仅凭 URL 证明实际 PDF 版号；没有版本身份的历史记录保持兼容。已知版号之间的隔离和跳转拒绝，不等于对所有外站内容做语义版本鉴定。
