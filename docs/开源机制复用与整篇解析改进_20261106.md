# 开源机制复用与整篇论文解析改进

日期：2026-11-06。目标沿用“稳定实现、能够展示、有据可循”，将原先的“篇内并发”扩展为“更好的整篇论文输入与理解”。本轮先完成免费、本地、可复现的机制对照，再决定接入；不把开源项目自报成绩当作本项目成绩。

## 开源项目实际采用什么机制

| 项目与一手材料 | 可借鉴的机制 | 与本项目的关系和决定 |
| --- | --- | --- |
| [Sentence Transformers](https://www.sbert.net/examples/sentence_transformer/applications/retrieve_rerank/README.html)、[LlamaIndex 的实现](https://github.com/run-llama/llama_index/blob/main/llama-index-core/llama_index/core/postprocessor/sbert_rerank.py) | 先召回，再用 Cross-Encoder 联合读取问题和候选文本，输出相关性分数 | 比独立向量相似度更直接建模问题与论文的关系。使用已有 sentence-transformers 运行环境，先免费实测小模型；不是继续调整被引量权重 |
| [SPECTER2](https://github.com/allenai/SPECTER2) | 面向科学文献表示，区分检索等任务适配器 | 科学领域有针对性，但不能把论文间相似度模型直接当成自然语言问题重排器；留作后续可比较路线，当前不叠加另一套大模型 |
| [PaperQA](https://github.com/Future-House/paper-qa) | 查询相关的证据检索、片段评分/概括及答案综合；可复用持久化索引 | 对“围绕某个问题找证据”适合；有额外调用、片段选择与压缩损失，不能直接代替完整论文阅读，也不能从其并发实现推导本项目必然提速 |
| [Docling](https://github.com/docling-project/docling)、[文档对象说明](https://docling-project.github.io/docling/concepts/docling_document/) | 将正文、标题、表格、图等组织为统一文档对象，以树中顺序表示阅读顺序 | 借鉴先恢复全文结构、再交给模型的路线。作为独立解析候选有价值，但当前不为已有功能引入整套依赖与模型部署 |
| [GROBID](https://github.com/grobidOrg/grobid) | 科学 PDF → 结构化 XML/TEI，识别章节、段落、引用等 | 很适合文献结构与引用关联；本地服务/Java 或容器部署超出轻量接入范围。本轮研究机制，不新增常驻服务 |
| [Marker](https://github.com/datalab-to/marker) | 版面/OCR、块合并、表格恢复；可选 LLM 校正 | 可借鉴对复杂块定向处理；启用 LLM 校正会增加调用与新的错误风险。其项目测量不作为本机速度证据 |
| [MinerU](https://github.com/opendatalab/MinerU) | 结构化解析、表格/公式等能力，提供不同本地质量层级 | 当前官方 basic 层可用 ONNX/CPU，并非所有路线都必须 GPU；但需额外模型下载和服务部署，本轮不抢先安装完整栈 |
| [ColPali](https://github.com/illuin-tech/colpali) | 直接对页面图像做多向量视觉检索 | 可覆盖文本抽取遗漏的图表，但解决的是视觉页面检索；当前文本模型不会因此自动获得图片理解能力，不是直接替换 parser 即可 |
| [MarkItDown](https://github.com/microsoft/markitdown) | 通用格式到 Markdown 转换 | 格式覆盖广，但没有证据表明在我们的科学 PDF 表格与章节任务上优于现有解析器，本轮不叠加 |
| [PyMuPDF4LLM](https://github.com/pymupdf/PyMuPDF4LLM)、[1.28.2 官方说明](https://pymupdf.io/blog/open-source-all-the-way-down-pymupdf4llm-goes-fully-agpl) | 已安装的 CPU 版面模型识别阅读顺序、标题与表格，然后导出全文 Markdown | **本轮优先接入**：不升级锁定包、不新增模型服务、不增加 LLM 分析轮次；实测后采用 layout，保留 legacy 回退 |

以上材料于本轮核对。开源项目版本会变化；本次接入实际固定在已有 PyMuPDF/PyMuPDF4LLM 1.28.2，而非直接升级最新主分支。

## 已落地：版面恢复后的整篇一次分析

流程为：`有效 PDF → CPU 版面解析 → 带标题/阅读顺序/表格的完整 Markdown → 一次单篇 LLM 分析 → 总体报告`。没有先生成分段笔记再综合的额外调用。图像、复杂公式的视觉理解仍不在当前文本模型能力之内。

原代码明确导入 `helpers.pymupdf_rag.to_markdown`，使用的是 legacy 路线；虽然依赖已包含 Layout，原项目并没有使用其结构解析结果。新版使用同一锁定版本的公开 `pymupdf4llm.to_markdown` 版面路径，明确关闭 OCR、图片嵌入与写出。页眉、页脚继续保留，避免为了缩短文本主动删掉内容。

新设置 `pdf_parser=layout` 为默认，对应 `PAPER_AGENT_PDF_PARSER=layout`；可设 `legacy` 使用原解析器。layout 抛出异常时仅回退一次 legacy，记录实际解析器、请求的解析器、异常类型和警告；若都失败，保留原文件和失败状态。自定义测试 parser 的错误仍按原语义处理，不被静默吞掉。所有 PDF 操作继续使用原全局锁，逐页映射与来源范围不改变。

单篇审计新增实际 `source_parser`，可核对模型收到的是哪种抽取结果。`fulltext` 继续表示完整已提取文本被提交，不表示 PDF 每个视觉元素或研究结论均已核实。

## 三篇真实公开论文的转换对照

使用已有公开 PDF 缓存，不下载新论文、不调用 LLM、不读取模型凭据。三篇均与上轮篇内实验的 LitSearch 文本样本不同，因此不能用这次结果替换上一轮失败记录。每篇做两轮；第一轮 legacy→layout，第二轮 layout→legacy，保留全部原始输出与 PDF 哈希。

| 公开论文 | 页数 | legacy 中位耗时 | layout 中位耗时 | 耗时降低 | Markdown 标题条数 legacy→layout |
| --- | ---: | ---: | ---: | ---: | ---: |
| Sequential Human Assembly and Disassembly Motions… | 11 | 11.02 s | 4.79 s | 56.6% | 3→16 |
| A Framework for Enhanced Human–Robot Collaboration… | 22 | 5.85 s | 4.95 s | 15.4% | 2→30 |
| Human–robot collaboration in building disassembly… | 10 | 3.20 s | 2.50 s | 21.9% | 1→21 |

计时仅覆盖本机 PDF 解析和正文生成，不包括下载、LLM 与最终报告。两轮为小样本，非统计稳定性或全系统提速保证。标题计数也不是标题准确率；layout 仍会把刊物信息标成标题。

第三篇的两个表格从 legacy 的 6 条 Markdown 表格行变为 layout 的 14 条。使用 Poppler 渲染 PDF 第 7 页并人工核对表 2：原来五个指标被拼成一个多行单元格；新版将各指标与三个实验分开对应，例如系统失败数对应 `0 / 1 (premature action) / Multiple hallucinations`。原 PDF 与模型生成结论没有被改写。

**仍有已知缺陷**：表 1 的长单元格仍有续行拆分；第一篇复杂合并表头仍存在文字切散；第二篇参考文献中的卷号 2198 在 layout 文本中缺失。基于 PDF 原始文本数字出现次数的启发式召回，三篇 legacy 为 0.98963/0.86222/1.00000，layout 为 0.98963/0.86080/1.00000；此指标受链接重复、数字分词和文献格式影响，既不能替代单元格关系核对，也不能证明无损。保留旧解析器及原 PDF 阅读入口。

因此本轮可以支持“转换阶段更快、章节结构更丰富、一个实表的指标对应恢复更好”，**尚不能支持 LLM 理解准确率已经提高或整套研究流程加速相同比例**。

## 排序：联合相关性判断，不再混合未校准的价值权重

新候选使用 `cross-encoder/ms-marco-MiniLM-L6-v2`，模型来源为 [官方模型卡](https://huggingface.co/cross-encoder/ms-marco-MiniLM-L6-v2)，固定 revision `233902d25c440f23af6f7d6e94d2946bac0bee0a`。这是英语 MS MARCO 检索相关性模型，不是论文质量或科学正确性裁判。

流程：保留现有语义/RRF 召回，只在原 Selector 的前 20 篇内联合读取查询与标题/作者关键词/摘要，再按相关性重排；原关键词、余弦、RRF 与 Selector 评分均保留。候选集合与第 20 名后顺序不动。模型输入上限 512 tokens；可能截断的 pair 单独审计，精选 Agent 仍读取原完整标题/摘要。超长查询、模型缺失或无效分数保留基线；不在正式任务中下载模型。CPU 执行，初次加载将本后端进程共享 PyTorch 的 CPU 线程数最多限制为 4，避免线程过度争用；无生成式 API 调用。

当前实现先用于冻结语料对照。公开模型下载曾因 HF 大文件传输停滞，改为有界公开 Range 下载并缓存；该环境准备耗时不计入推理时间。新增未见查询组尝试通过 Semantic Scholar 解析 gold 元数据时收到 HTTP 429，未将失败数据当作完整测试集，也没有改用未授权 key。

首轮先尝试前 40 篇重排：首组 nDCG@5 从 0.719220 提高到 0.806546，但 Recall@20 从 0.975 降到 0.950。因此仅根据首组结果修正范围为原前 20 篇，在查看第二组新 Cross-Encoder 结果前固定此规则，不调整模型或权重。以下为最终二十篇版本的真实本地模型测量：

| 固定查询组 | 候选数 | 原语义/RRF nDCG@5 | 联合重排 nDCG@5 | 原/新 Recall@20 | 重排耗时中位数（首题外） |
| --- | ---: | ---: | ---: | ---: | ---: |
| LitSearch 第 1–20 题 | 146 | 0.719220 | 0.806546 | 0.975 / 0.975 | 1.52 s |
| LitSearch 第 21–40 题 | 141 | 0.748784 | 0.915853 | 0.908333 / 0.908333 | 1.50 s |

这是有收益的**候选前排相关性回归**：未保护前五名，nDCG@5 增加来自模型重排。Recall@20 相等由保留候选集合直接保证，不当作新的召回收益。两组分别有 6/7 题改善、2/1 题退化，其余持平，不能保证每个问题更好。第一组是范围修正时已用过的数据；第二组之前用于手写价值规则，本轮没有用于拟合模型或调权重，不称为独立盲测。

每组候选是先前固定三主题背景加上各题 gold 元数据的构造集合，不是完整 LitSearch 语料或在线检索。第二组两个 gold 未解析仍保留分母。尚未运行最终 LLM Selector 的同输入对照，不能把该结果说成最终 Top-k、论文参考价值或报告质量提高。两条路线的模型和输入窗口均不同，也没有做等窗口长度消融。

**接入决定：可切换，默认关闭。** `PAPER_AGENT_CROSS_ENCODER_ENABLED=true` 开启，普通 Demo 不加载模型；与旧 `VALUE_RANKING_ENABLED=true` 互斥，避免叠加未经验证的规则。实际方法与降级记录在 `metrics.ranking.cross_encoder`，论文保留 `cross_encoder_score/rank/model`；Selector 将分数作为辅助相关性线索，执行记录说明分数不是概率或科学质量判断。首次应提前缓存权重，当前机器已准备好。先前手写价值规则的退化结果原样保留。

## 本轮验证

- 解析器及恢复检查：真实小 PDF、真实表格、逐页映射、扫描/乱码/失败边界，layout 故障回退与 legacy 显式配置。
- 真实 MainAgent→官方 MCP→实际 layout 转换→整篇一次笔记→总体报告链路检查通过；论文和模型均是标记的合成夹具，仅证明链路组合，0 次收费请求。
- 修复上轮无 Markdown 标题时跳过段落回退的缺陷；保留分段实验默认关闭。新增无标题完整句子切分回归。旧失败实验不重写。
- 最终 Python **463 passed、3 skipped**；Ruff、`pip check`、TypeScript、生产构建和 `git diff --check` 通过；前端 18 passed；Electron 17 passed、1 packaging skipped。源码桌面完整 E2E 22 组通过，[最终结果记录](../data/validation/v020/source-1793980653401/result.json)。桌面流程使用明确标记的合成模型，不作为真实 LLM 质量验证。
