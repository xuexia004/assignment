# PR 候选版实验结果与问题归因

本文保留综合报告修复前的原始结果。随后已完成结构化报告与一次格式恢复，并用同五篇另做配对验证；最新状态见 [综合报告修复与对照实验](综合报告修复与对照实验_20261116.md)。下文“待修复”和旧默认描述属于该次历史诊断，不代表后续修复未实施。

本次实验支持保留已有多篇并行和各方法的对照开关，但尚未证明新增方法让系统整体稳定更快、更准。长等待主要集中在原文获取；报告失败存在新旧版本共有的输出截断问题；新增证据方法还有引句校验失败。以下结果用于 PR 审查及小组进展沟通，问题定位不代表修复已经完成。

## 实验范围和统计口径

输入统一为 PPT 第 19 页范例“长期记忆如何降低 Agent 的推理成本？”，目标 5 篇。使用相同本机 Python 环境、`deepseek-flash`、关闭 thinking、温度 0；关闭应用缓存，独立任务目录，不写回用户配置。未重建历史依赖环境，供应商缓存及网络状态无法固定。

指标分开计数：**可读正文**指拿到可读文本，可以不完整；**覆盖完整**是转换器文本覆盖判据，不代表图表、公式或事实完整；**可用笔记**通过结构及内容检查，不等于回答事实准确；**可读报告**是有效报告内容，失败占位文件不算；**严格全文报告**还要求所有输入的全文/笔记及引用满足完整性条件。

## 为什么数据不理想

### 原文获取链路波动及重试拉长等待

相同 PDF、候选 URL、最终 URL，均为两次请求、零次重试、一次重定向，下载却为 4.547、232.906、17.312 秒。它证明同文件、同请求结构也有明显链路波动，不能继续定位到本机网络、远端服务器或 CDN 中的具体一层。

历史串行第三轮全文耗时 1091.71 秒，总计 1224.98 秒：原选一篇和前九个候补失败，第十个候补成功，合计尝试 15 篇。保留的 12 条候选错误均为连接超时，但内部每次重试历史不完整，不能把全部等待解释成某一种连接错误。该轮仍在候选版 1200 秒总期限和额外 10 篇候补范围内，不能只凭新增预算上限就断定它导致新旧差别。

### 新旧共有的报告输出设置与生成结果不匹配

两版都把完整笔记交给一次模型请求，要求完整 Markdown 和结构化字段，输出上限 4000 token，并严格检查结构和引用；direct 路径没有格式修复或续写。固定文档 12 次都明确观察到 `length` 截断，是需要修的共同问题。提高网络等待不能让已经到达输出上限的回答继续生成。

33 轮报告失败包含 18 次 `output_truncated`、6 次 schema 错误、2 次 JSON 解析失败，另 3 次因无可用笔记跳过生成，4 次报告可读。旧日志的 `output_truncated` 也可能由内容过滤触发，不能把这 18 次都断言为长度截断；明确的 12 次 `length` 证据来自后续固定文档回放。只加输出预算也不能保证同时解决格式错误。

### 新增证据方法存在引句匹配失败

33 轮单篇分析失败中，37 次为 `citation_quote_mismatch`，另有 4 次 schema、2 次 JSON 解析失败。证据路径要求引句与选定原文的连续字符串匹配，一处不匹配即可拒收整篇，缺少受约束修复；direct 没有这条引用校验路径。这是新增方法需要处理的问题，不能用网络或 API 不可用解释，也不能简单删掉校验来提高成功数。

### 正文覆盖与选文变化影响对比

原有 legacy 解析核心、质量阈值和 PDF 运行锁均相同；历史对照没有开启新 layout，不能将其结果归因于 layout。33 轮中按 PDF 哈希匹配的 15 组跨解析器观察有 6 组覆盖判定改善、9 组持平、0 组退化；这支持覆盖层面的有限收益，不证明回答更准。

查询规划和 Selector 使用模型，重复输入也不保证最终论文相同；历史版自身也出现候选相同而规划措辞、最终选文变化。当前 Selector 即使关闭扩展，系统提示词仍增加 433 UTF-8 字节，因此关闭开关不等于历史请求完全相同。固定文档回放才排除了这部分输入差异。

## 核心代码变化与提交判断

| 环节 | 历史版与候选版的差异 | 审查结论 |
| --- | --- | --- |
| 并行与按排名替补 | 两版原 Top-k 都是 gather＋信号量，候补都按排名分批等待 | batch 不是相对该历史版新增的提速技术，也没有新增原 Top-k 固定三篇屏障 |
| 替补成功条件 | 从有 PDF 改为有可读正文；无可读正文时继续补位 | 改善目标合理，但可能多请求、多等待；本次未隔离证明其因果收益 |
| 下载预算 | 新增全文总期限及候补数限制；等待来源门不再耗尽地址计时 | 控制等待范围，不改变实际网速；PDF connect=5 秒仍是共有行为 |
| 文件身份 | 新增 arXiv 版本校验、任务隔离及哈希记录 | 正确性保护；本轮缓存关闭，不宣称缓存提速 |
| PDF 解析 | legacy 核心相同；新增可选 CPU layout，异常时回退 legacy | 低覆盖但不抛异常不会自动回退；覆盖指标不等于语义质量 |
| 单篇与综合 | direct 提示词、schema、报告核心及模型客户端相同；新增分析方法与更细诊断 | 报告共有缺陷与新增证据失败应分别修复 |

建议保留多篇并行、默认 direct、按排名替补和基线开关。下一步优先处理报告篇幅/输出预算及有界格式修复，再处理引句定位与有界修复，最后把连接、读取、排队和总期限分开诊断与调节。**这些是待办，不是本次已交付的修复。** 小组可以据此决定补修后合并，或带明确限制审查候选版；不把负结果删掉后宣称全优化已经优于基线。
